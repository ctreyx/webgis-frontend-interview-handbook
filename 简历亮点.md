#### ⭐ 亮点一：requestIdleCallback 空闲调度优化雷达动画（最大亮点）

```
┌──────────────────────────────────────────────────────┐
│                                                       │
│  问题：                                               │
│  Cesium 初始化时需要同时解压缓存 15 个雷达数据压缩包，  │
│  解压过程严重占用主线程资源，导致地图初始化期间           │
│  交互卡顿、动画掉帧，用户体验极差。                     │
│                                                       │
│  分析：                                               │
│  解压操作是 CPU 密集型任务，与地图渲染、用户交互         │
│  共同争抢主线程资源。雷达数据缓存优先级低于地图交互，    │
│  不需要立即完成，适合在浏览器空闲时分批执行。            │
│                                                       │
│  方案：                                               │
│  采用 requestIdleCallback 空闲调度策略，将 15 个        │
│  压缩包拆分为单个任务，每次仅在浏览器空闲时解压一个，    │
│  不阻塞地图渲染和用户交互。                             │
│                                                       │
│  同时针对 Safari 等不支持 rIC 的浏览器，               │
│  自研了 rIC polyfill：                                 │
│  基于 requestAnimationFrame + MessageChannel 实现，    │
│  rAF 获取每帧起始时间计算 16.6ms 帧截止时间，          │
│  MessageChannel 在帧渲染完成后触发宏任务，              │
│  通过 performance.now() 判断当前帧剩余时间，            │
│  有空闲才执行解压回调。                                 │
│  该方案与 React Scheduler 的时间切片原理一致。          │
│                                                       │
│  结果：                                               │
│  地图初始化期间交互流畅度显著提升，                      │
│  雷达动画缓存在后台静默完成，                           │
│  用户无感知，全浏览器兼容。                             │
│                                                       │
└──────────────────────────────────────────────────────┘
```

#### ⭐ 亮点三：Cesium 万级站点渲染性能优化

```
┌──────────────────────────────────────────────────────┐
│                                                       │
│  问题：                                               │
│  全国气象站点数据量达万级，使用 Cesium Entity API       │
│  渲染时出现明显卡顿，帧率下降严重。                     │
│                                                       │
│  分析：                                               │
│  Entity 底层存在三层性能开销：                          │
│  1. Property 系统每帧对所有实例调用 getValue(time)     │
│     万级实体 × 多个属性 = 每帧数万次求值               │
│  2. Visualizer 每帧做 Entity → Primitive 转换         │
│  3. 每个 Entity 独立 DrawCall，无法合批                │
│                                                       │
│  方案：                                               │
│  · 用 Primitive + PrimitiveCollection 替代 Entity     │
│    跳过 Property 系统和 Visualizer 转换开销            │
│    同类型几何体合批渲染，DrawCall 从数千次降至个位数    │
│  · 视口裁剪：只渲染当前可视范围内的站点               │
│  · 层级抽稀：根据 zoom 等级动态控制数据密度            │
│    高层级显示省级站点，低层级显示所有站点               │
│                                                       │
│  结果：                                               │
│  万级站点流畅渲染，帧率稳定在 60fps。                  │
│                                                       │
└──────────────────────────────────────────────────────┘
```

#### ⭐ 亮点一：自研全局事件派发系统（架构亮点）

```
┌──────────────────────────────────────────────────────┐
│                                                       │
│  背景：                                               │
│  大屏项目中地图组件需要被多个业务组件控制               │
│  （如飞行定位、图层切换、数据刷新等），                  │
│  且组件间不一定有父子关系。                             │
│  defineExpose + ref 方式必须有父子关系，               │
│  且跨多层组件不好用。                                  │
│  全部放 Pinia 会导致状态管理混乱。                     │
│                                                       │
│  设计方案：                                            │
│  参考 Vue3 响应式源码的依赖收集机制，                   │
│  设计了三层 Map 数据结构：                              │
│                                                       │
│  targetsMap(Map)                                      │
│    → componentKeyDeps(Map)                            │
│      → deps(Set<Handler>)                             │
│                                                       │
│  对应 Vue3 源码的：                                    │
│  targetMap(WeakMap)                                   │
│    → depsMap(Map)                                     │
│      → dep(Set<ReactiveEffect>)                      │
│                                                       │
│  对外暴露三套 API：                                    │
│  · useGlobalPropsListener — 注册监听                  │
│  · useGlobalPropsEmitter  — 触发事件                  │
│  · useGlobalPropsOff      — 解除监听                  │
│                                                       │
│  技术细节：                                            │
│  · TypeScript 泛型约束事件参数类型                     │
│  · Set 自动去重防止重复注册                            │
│  · 支持跨组件、跨层级通信，不依赖父子关系              │
│                                                       │
│  效果：                                               │
│  · 地图组件对外通信解耦，新功能接入无需改原有架构       │
│  · 代码语义清晰，可维护性高                            │
│  · 配合使用文档，团队成员快速上手                      │
│                                                       │
└──────────────────────────────────────────────────────┘
```
