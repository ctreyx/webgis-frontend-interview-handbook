
 

### 正确关系（重点）

**三个生命周期（bootstrap / mount / unmount）是子应用必须导出的。**

- 子应用在自己的入口文件（通常是 `src/main.js` 或 `src/public-path.js` + 入口）里 **export** 这三个函数。
- 主应用（基座）通过 `registerMicroApps` 注册子应用后，qiankun 会去加载子应用的 JS 资源，**拿到子应用导出的这些生命周期函数**。
- 之后当路由匹配、子应用需要激活/失活时，**由 qiankun（基于 single-spa）来调用**这些函数。

所以：
- 它们**不是**基座自己写的，而是**子应用提供、基座调用**的。
- 基座**可以**在注册时额外配置自己的生命周期钩子，用来监听或包装子应用的生命周期。

 

**子应用（必须写）：**
```js
// 子应用入口
let app = null

export async function bootstrap() {
  console.log('子应用 bootstrap')
}

export async function mount(props) {
  console.log('子应用 mount', props)
  // 创建实例并挂载到 props.container
  app = createApp(App)
  app.mount(props.container ? props.container.querySelector('#app') : '#app')
}

export async function unmount(props) {
  console.log('子应用 unmount')
  app?.unmount()
  app = null
  // 在这里做各种清理
}
```

**主应用（基座）：**
```js
registerMicroApps([
  {
    name: 'child-app',
    entry: '//localhost:8081',
    container: '#subapp-container',
    activeRule: '/child',
    props: { /* 传给子应用的数据 */ },
    // 可选：基座自己的生命周期钩子（用来监听）
    loader: (loading) => { ... },
    // 或者更完整的 lifeCycles
  }
], {
  // 全局生命周期钩子（基座监听）
  beforeLoad: [async (app) => console.log('before load', app.name)],
  beforeMount: [async (app) => console.log('before mount', app.name)],
  afterMount: [async (app) => console.log('after mount', app.name)],
  beforeUnmount: [async (app) => console.log('before unmount', app.name)],
  afterUnmount: [async (app) => console.log('after unmount', app.name)],
})

start()
```

**总结一句话：**
- 子应用：**导出** bootstrap / mount / unmount
- 基座：**调用**这些导出的函数，同时可以自己注册钩子去**监听**这些时机

 

 # “子应用的生命周期我们是严格按照 qiankun（基于 single-spa）的规范来处理的。

子应用必须导出三个生命周期钩子：

bootstrap：只执行一次，在子应用第一次加载时调用，主要做一些全局初始化的工作，比如注册全局组件、初始化第三方库、配置请求拦截器等。
mount：每次子应用被激活（路由匹配）时调用，这时候会接收到主应用传过来的 props。我们在这里创建 Vue/React 实例，并挂载到 props.container 指定的 DOM 节点上。
unmount：每次子应用失活时调用，必须在这里做完整的清理，否则很容易出现内存泄漏和事件残留。
为了兼容「独立运行」和「被 qiankun 加载」两种模式，我们通常会这样写：

JavaScript

if (window.__POWERED_BY_QIANKUN__) {
  // 导出三个生命周期
  export async function bootstrap() { ... }
  export async function mount(props) { ... }
  export async function unmount(props) { ... }
} else {
  // 独立运行时直接挂载
  render()
}
卸载时的清理是我重点关注的地方，主要做这几类：

框架实例销毁：Vue3 调用 app.unmount() 并清空容器，React 对应 unmountComponentAtNode。
事件清理：window/document 上的监听、自定义事件全部移除。我之前针对 EventBus 内存泄漏问题，手写了一套基于 WeakMap + Map + Set 的事件中心，并利用 Vue3 的 getCurrentInstance + onUnmounted 实现自动收集和自动解绑，所以在 unmount 时可以很干净地统一清理，降低开发者心智负担。
定时器和异步任务：clearTimeout/clearInterval，用 AbortController 取消请求，关闭 WebSocket。
第三方实例销毁：ECharts、地图（高德/百度）、视频播放器等必须调用 dispose/destroy。
全局变量恢复：尽量删除或还原挂在 window 上的变量。
真实踩过的坑：早期有一次子应用切换后，地图的点击事件还在触发，控制台一直报错，内存也涨。排查后发现是 unmount 时既没有销毁地图实例，也没有解绑事件。后来我们把清理逻辑做成了强制 checklist，并在 code review 和 AI 门禁里增加了相关检查。

同时 unmount 我们会做成幂等的，防止被多次调用出错。通过这些措施，子应用切换非常稳定，长时间使用也不会出现越来越卡的情况。”
