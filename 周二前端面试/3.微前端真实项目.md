“微前端主要解决大型项目多团队协作、技术栈不统一、模块需要独立开发部署的问题。传统 iframe 虽然隔离强，但有样式隔离失效（其实是弹窗逃逸）、路由历史丢失、白屏、通信麻烦等体验问题。

我实际用得最多的是 qiankun。它基于 single-spa，核心做了三块：

HTML Entry：主应用配置子应用的 name、entry（html 地址）、container，路由变化时 fetch 子应用 index.html，自动解析并加载里面的 JS/CSS；
沙箱隔离：默认 ProxySandbox，给每个子应用创建一个 fakeWindow，用 Proxy 拦截 get/set，真正实现多实例隔离；还有 SnapshotSandbox（单实例，mount 前快照 window，unmount 时还原）做降级；
样式隔离支持 Shadow DOM 或实验性前缀。生命周期就是子应用导出 bootstrap/mount/unmount，主应用负责调度。

在天府科技项目中，我们有开发态、运行态、运维态三个平台，开发态改完逻辑后需要实时嵌入运行态做预览，就用 qiankun 把运行态作为子应用加载进去，通过 props 下发数据和权限，公共依赖用 externals 抽离，解决了多技术栈（低代码部分是 React）和独立发版的问题。

对比其他方案：iframe 隔离最强但体验差；Module Federation 性能最好、适合同栈模块共享；wujie 用 iframe+Shadow 做更强隔离且零改造；micro-app 用自定义元素，接入最简单。2022 年我们选 qiankun 是因为它当时最成熟、对多技术栈和遗留系统支持最好。

从架构角度看，我把主应用做成稳定的 shell（权限、布局、公共组件库），子应用独立仓库 + 独立 CI/CD，最终实现并行交付和资产沉淀，复用率明显提升。微前端不是银弹，关键是把基座做稳，子应用能真正独立演进。”
