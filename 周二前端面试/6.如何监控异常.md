# 优化后的企业级口语完整版（约 1 分 50 秒 – 2 分 10 秒，强烈建议直接背这个）


“微前端异常捕获上报我们采用分层 + 标准化的企业级方案，保证一个子应用挂了不影响主应用，同时能精准归因。

基座侧（主应用）做统一兜底： qiankun 提供了两个关键 API：

addErrorHandler（来自 single-spa）：专门捕获子应用生命周期错误，比如加载 HTML Entry 失败、bootstrap/mount/unmount 报错，能拿到具体是哪个 app、是启动阶段还是运行阶段。
addGlobalUncaughtErrorHandler：监听 window 的 error 和 unhandledrejection，捕获运行时未处理异常。
在这两个 handler 里，我们解析错误，自动带上当前激活的子应用 name、错误类型（加载失败 / 运行时 / 资源 404）、堆栈、路由等信息，然后上报。

子应用侧必须主动捕获：

用 window.addEventListener('unhandledrejection') 和 window.onerror。
Vue 用 app.config.errorHandler，React 用 ErrorBoundary 的 componentDidCatch。
主应用通过 props 下发统一的 reportError 方法，子应用捕获后调用它，自动附带 appName、版本号。
上报标准化： 每条错误固定格式：错误类型、应用名称、当前 url/路由、用户信息、浏览器环境、时间戳、堆栈、build 版本。我们通常接 Sentry（用 tag 区分子应用）或自研监控，CI 里自动上传 sourcemap，支持采样、去重和告警。

实际在天府科技三态项目里，开发态嵌入运行态时，运行态组件报错能精准报到‘runtime-app + 具体路由 + 版本’，主应用和其他态不受影响，还做了 ErrorBoundary 降级 UI。公共上报 SDK 也沉淀到了 monorepo 组件库，新子应用接入成本很低。

这套机制让微前端在独立交付的同时具备完整可观测性，出问题分钟级定位到团队，完全符合架构设计和资产沉淀的目标。”
