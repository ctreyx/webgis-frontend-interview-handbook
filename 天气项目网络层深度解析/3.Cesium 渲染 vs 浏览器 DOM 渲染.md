# Cesium 渲染 vs 浏览器 DOM 渲染

# 根本性区别

┌──────────────────────────────────────────────────────────────────┐
│ 两套完全不同的渲染体系 │
│ │
│ DOM 渲染体系 Canvas/WebGL 渲染体系 │
│ ───────────────────── ───────────────────────── │
│ 浏览器内置渲染引擎 应用自建渲染引擎 │
│ 声明式（描述"是什么"） 命令式（描述"怎么画"） │
│ 浏览器决定何时/怎么渲染 应用完全控制渲染帧 │
│ 有 Layout/Paint 开销 无 Layout 概念 │
│ CPU 主导 GPU 主导 │
│ │
│ ★ Cesium 完全绕过浏览器渲染流程！ │
│ 它接管了 <canvas> 元素，直接调用 WebGL API 操控 GPU │
└──────────────────────────────────────────────────────────────────┘

# 总结

1.  dom是浏览器内置渲染引擎 cesium是应用自建渲染引擎
2.  一个有layout/paint ，一个没有layout
3.  一个cpu主导，一个gpu主导

# Canvas 和 DOM 本质区别总结

┌────────────────┬──────────────────────────┬──────────────────────────┐
│ 维度 │ DOM 渲染 │ Canvas/WebGL 渲染 │
├────────────────┼──────────────────────────┼──────────────────────────┤
│ 渲染主体 │ 浏览器渲染引擎 │ 应用自己的渲染引擎 │
│ 事件模型 │ 原生事件冒泡/捕获 │ 需手动做碰撞检测 │
│ 像素操作 │ 无法直接访问 │ 完全掌控每个像素 │
│ GPU 利用 │ 合成层才能用 GPU │ 全程 GPU │
│ 内存模型 │ 保留模式（浏览器管理对象）│ 即时模式（画完即忘） │
│ 可访问性 │ 内置（ARIA） │ 需要额外实现 │
│ SEO │ 天然友好 │ 内容不可索引 │
│ 调试工具 │ DevTools Elements │ WebGL Inspector │
│ 变化响应 │ 自动（浏览器脏标记） │ 手动 requestAnimationFrame│
└────────────────┴──────────────────────────┴──────────────────────────┘

# 完全绕过 DOM 渲染流程，自建 WebGL 渲染引擎，直接 GPU 操控

DOM 渲染： 浏览器引擎接管 → Layout → Paint → Composite → CPU 计算布局和绘制→ 最终合成阶段才交给 GPU → 开发者只能间接控制（改样式）

Canvas / WebGL 渲染（Cesium）：开发者完全接管 → 浏览器只提供画布 → Cesium 自己管理渲染循环（requestAnimationFrame） → 自己做相机/光照/着色器计算 → 直接调用 WebGL API 提交 GPU DrawCall
→ 完全绕过浏览器的 Layout 和 Paint 阶段
