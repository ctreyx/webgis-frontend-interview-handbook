1. 最大重连次数，指数退避，不能无脑重连，第一次间隔1s,第二2s...

2. 页面可见性，比如息屏，需要暂停心跳，页面回复再连接

```js

   document.addEventListener('visibilitychange', () => {
     if(document.hidden) {
       this.pauseHeartbeat() // 息屏暂停心跳
     } else {
       // 页面恢复，检查连接状态
       if(this.ws.readyState !== WebSocket.OPEN) {
         this.reconnect()
       }
     }
   })
 }
```

# 首先：为什么需要心跳？

面试官，WebSocket 有一个很隐蔽的问题：
连接断了，不一定会触发 onclose

正常断链：onclose 会触发 ✅

但这些情况 onclose 不触发 ❌：

- 用户网络中断（断网但没关页面）
- 运营商/代理服务器把空闲连接强制掐断
- 服务器假死（进程还在但不响应）
- NAT 超时（路由器把空闲连接踢掉）
  这种情况叫假连接/僵尸连接
  ws.readyState === OPEN 但实际上数据发不出去
  天气项目中用户看到的是数据静止不更新，但页面没有任何报错
  非常难排查，用户会以为是气象数据没变化

# 心跳机制核心原理

客户端每隔 N 秒发一个 ping
服务端收到 ping 回一个 pong
客户端收到 pong → 连接正常，重置计时器
客户端超时没收到 pong → 判定连接断了 → 主动关闭 → 重连

# 总结

心跳本质是：用应用层的 ping/pong 来检测传输层的连接是否真实存活
因为 TCP 的断链感知在移动网络/NAT/代理环境下极不可靠
心跳 + 指数退避重连 + 重订阅，三件套缺一不可
