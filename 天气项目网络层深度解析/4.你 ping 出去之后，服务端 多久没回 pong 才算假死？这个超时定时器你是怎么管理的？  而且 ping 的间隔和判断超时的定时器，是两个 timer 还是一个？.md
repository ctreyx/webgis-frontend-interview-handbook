# 4.你 ping 出去之后，服务端 多久没回 pong 才算假死？这个超时定时器你是怎么管理的？  而且 ping 的间隔和判断超时的定时器，是两个 timer 还是一个？

1. 超时定时器管理


let pingTimer = null   // 定时发送 ping
let pongTimer = null   // 等待 pong 超时判断

function startHeartbeat() {
  pingTimer = setInterval(() => {
    ws.send('ping')
    
    // 发完 ping，启动 pong 超时检测
    pongTimer = setTimeout(() => {
      // 超时没收到 pong → 判定假死
      ws.close()
      reconnect()
    }, 3000) // 3秒内没回pong就假死
    
  }, 10000) // 每10秒发一次ping
}

// 收到 pong 时，清掉超时定时器
ws.onmessage = (e) => {
  if (e.data === 'pong') {
    clearTimeout(pongTimer)
  }
}



# 怎么定这两个值？
ping 间隔取决于：

你们天气数据推送频率是多少？如果本身 5s 推一次数据，服务端其实可以用数据本身当心跳，不需要额外 ping
服务器连接数多少？连接越多，ping 间隔应该越长，减少服务器压力
pong 超时取决于：

用户网络环境，政府内网延迟低，2s 够了
如果是面向公网用户，可能要放宽到 5s



# 面试中正确的回答姿势
❌ "ping 间隔 10s，pong 超时 3s"

✅ "具体数值要结合业务定，我们项目是内网环境，实时性要求高，所以 ping 间隔定的比较短，pong 超时定的比较严，如果是公网就要适当放宽"

记住：面试官给你看具体数字，是为了帮你理解概念。真实面试里你说出"根据场景决定"，比背一个数字更加分。
