# 重连成功之后，断线期间丢失的 WS 消息怎么处理？

比如天气数据实时推送，断线 10 秒，这 10 秒的数据怎么办？



断线期间丢失消息的处理
这个没有唯一答案，看业务场景，一般有三种策略：

# 策略一：直接丢弃（最简单）
天气数据是实时性数据，断线 10 秒的历史数据没有意义，重连后直接拿最新数据就行。

✅ 适合你们天气项目，实时推送丢了就丢了，不影响当前状态。

# 策略二：重连后主动拉取（补偿）
JavaScript

ws.onopen = () => {
  // 重连成功后，主动请求断线期间的数据
  http.get('/api/weather/missed', { 
    from: lastMessageTime,
    to: Date.now() 
  })
}
✅ 适合标注数据、告警数据这类不能丢的场景

# 策略三：服务端消息队列（最完整）
服务端给每条消息加 messageId，客户端重连时带上最后收到的 messageId，服务端从这个 ID 之后重新推送。

✅ 适合多人协作标注这类强一致性场景，类似你们的多人标注功能
