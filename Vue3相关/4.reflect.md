# reflect 的作用

完成对象基本操作，我们不管新增删除对象，都是 间接 使用对象基本操作，比如obj.a=1 , 新增就是用了set操作。、

es6以前我们都无法直接操作对象基本方法，但是现在reflect可以操作，比如reflect.OwnKeys(obj),可以拿到Obj所有key，和obj.keys()对比，obk.keys无法拿到枚举的key.

```js
const obj = {
  a: 1,
  b: 2,
  get c() {
    return this.a + this.b;
  },
};

// 如果我们打印obj.c，返回3很正常，但是this哪来的？实际上是对象基本操作get(obj,key,this)，浏览器自己传的this进去，现在有reflect就可以灵活传入this

// 那么vue3为什么要用reflect?
proxy(obj, {
  get(target, key, receiver) {
    return target[key]; //这样实际上无法拦截 c里面的this.a+this.b ，这就是关键，所以必须 reflect(target,key,receiver) 才能拦截
  },

  //   第二个原因：返回值语义正确
  set(target, key, value, receiver) {
    const result = Reflect.set(target, key, value, receiver);
    // ↑ 返回 boolean，表示 set 是否成功
    // 严格模式下，set trap 必须返回 boolean
    // 不用 Reflect 直接 target[key] = value，返回 undefined → 严格模式报错
    if (result) {
      trigger(target, key); // 只有 set 成功才触发更新
    }
    return result;
  },
});
```

问题出在哪：

访问 proxy.name
↓
触发 get trap，执行 target[key]
↓
target 是原始对象，所以 getter 里 this = target（原始对象）
↓
this.\_name 等价于 target.\_name
直接访问原始对象，完全绕过了 Proxy！
↓
\_name 的依赖追踪丢失，\_name 变化不会触发更新 ❌
