# vue3 diff

Vue3 的 diff 核心是 patchKeyedChildren，我把它分三个阶段来讲：

第一阶段是头尾预处理。 定义指针 i 从头部开始，e1、e2 分别指向新旧数组的尾部。先从前往后比，key 和 type 相同的节点直接递归 patch 复用，i 往右走；再从后往前比，同样相同就 patch，e1、e2 往左收。这一步的目的是快速跳过首尾相同的节点，缩小中间的乱序区间。

预处理完之后先做一个简单判断：如果旧的比完了新的还有剩余，说明是纯新增，批量挂载；反过来就是纯删除，批量卸载。大多数日常场景到这一步就结束了。

第二阶段是乱序处理。 如果中间两边都有剩余，先遍历新的中间段，建一个 keyToNewIndexMap，就是新节点的 key 到索引的映射。然后遍历旧的中间段，逐个去映射表里查——查到了就 patch 并记录到 newIndexToOldIndexMap，查不到说明新序列里没有这个节点了，直接卸载。

第三阶段是最长递增子序列。 对 newIndexToOldIndexMap 求 LIS，LIS 中的节点说明相对顺序没变，不需要移动；不在 LIS 中的才执行 DOM 移动。然后倒序遍历新的中间段，因为倒序时后面的位置已经确定，可以直接用 insertBefore 插到正确位置。oldIndex 为 0 的就是新增节点，执行挂载。

这样就把 DOM 操作降到了理论最小值。




# vue3 最长递增子序列

"最长递增子序列 在 Vue3 diff 中的作用是找出中间乱序区间里，哪些节点的相对顺序本来就没变。这些节点不需要移动 DOM，只需要移动不在 LIS 中的节点，从而把 DOM 操作降到最少。

算法实现是贪心 + 二分：维护一个 tails 数组，记录不同长度递增子序列的最小末尾值。通过newIndexToOldIndexMap 映射新节点在老节点的位置，然后开始遍历，如果当前值大于 tails 末尾就追加，否则二分找到第一个大于等于它的位置替换——这样保证末尾值尽可能小，给后面的元素留更多接上来的空间，这就是贪心的思想。

但 tails 本身不是真正的 LIS，所以 Vue3 额外维护了一个前驱数组 predecessor，最后从 tails 末尾沿前驱链回溯，才能拿到真实的 LIS 索引序列。整体时间复杂度 O(n log n)。

Vue 2 的 Diff（双端比较）
核心在 patch → patchVnode → updateChildren。

流程：新旧子节点使用四个指针（oldStart/oldEnd/newStart/newEnd），按优先级做四种比较：
旧头 vs 新头
旧尾 vs 新尾
旧头 vs 新尾（交叉）
旧尾 vs 新头（交叉）
匹配则复用并 patchVnode，指针向中间收缩；不匹配则用 key 做线性查找（或按索引），找到后移动，找不到则新建。
剩余节点批量新增或删除。
特点：纯运行时启发式优化，适合常见头尾操作场景；全量递归遍历 VNode 树，静态节点也参与比较；无 key 时性能较差；乱序复杂时可能产生多余移动。
 

 
Vue 3 的 Diff 与整体更新优化
Vue 3 重写了相关逻辑（主要在 patchKeyedChildren 等），并大幅引入编译时信息。

编译时优化（最大提升来源）：

静态提升（Static Hoisting）：静态节点/子树提升到渲染函数外，只创建一次，后续直接复用。
PatchFlag：编译器给动态节点打标记（如 TEXT、CLASS、PROPS、FULL_PROPS 等），运行时只更新标记的部分，静态直接跳过。
Block Tree：把动态子节点收集成“块”，更新时只遍历动态部分，大幅缩小 Diff 范围。
事件处理函数缓存等，减少不必要重建。
