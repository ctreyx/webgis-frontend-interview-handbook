# ai 门禁


痛点： 刚进公司时为了规范，我推动建立了 Code Review 制度。但项目一繁忙，团队反馈很明显：CR 严重拖慢效率、打断开发节奏，而且很多审查流于形式，质量反而无法保证。ESLint 只能覆盖语法和简单规则，对「定时器/事件监听是否真正清理」「组件是否合理抽离成 hooks」「逻辑是否该下沉到组件库」这些语义问题无能为力。

解决方案（两层门禁）：

我设计了确定性规则 + AI 语义审查的两层架构：

第一层：确定性静态扫描（零成本、极速）

用 Node.js 的 child_process 执行 git 命令（git diff + git ls-files），快速获取全仓可疑文件。
通过精心维护的正则规则预筛，例如：
出现 setInterval/setTimeout 必须能匹配到对应的 clear 逻辑
出现 addEventListener 或事件绑定，必须有对应的解绑
地图实例、Cesium/QE 相关对象是否有销毁
全仓库 36 万行代码扫描仅需 423ms，0 token 成本。

第二层：AI 语义审查（精准、低成本）

只把「本次 git diff 变更文件 + 第一层命中的可疑文件」喂给 AI，输入量相比全量降低 99%，单次成本约 ¥0.01。
把团队规范、组件库使用标准、hooks 抽取原则、组件拆分标准等写成 System Prompt，团队级提示词。
AI 负责判断 ESLint 做不到的语义问题：解绑是否在其他文件、是否存在真正的内存泄漏风险、组件是否该抽离、是否违反了我们组件库的接入规范等。
同时设计了完善的忽略机制（内容指纹 + 元信息 + 过期策略），避免误报反复打扰。

效果：

Code Review 从机械性、低价值的检查中解放出来，现在 Review 主要聚焦业务逻辑和架构设计。
单次 Review 耗时估计节省约三分之一。
门禁先在单项目验证，后推广到全部项目线，沉淀为公司可复用的代码质量基础设施。
