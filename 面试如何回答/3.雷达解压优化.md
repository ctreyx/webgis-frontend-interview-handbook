# 为什么raf 能实现这个功能
rAF 提供帧的起始时间戳，MessageChannel 把执行推迟到帧渲染完成之后，两者配合就能在帧末尾精准判断是否还有空闲时间。这和 React Scheduler 的实现是同一条思路。

## 问题背景

雷达动画需要解压 **15 个压缩包**并缓存到内存，直接同步解压会抢占主线程，导致地图初始化卡顿。

## 解决方案

使用 **requestIdleCallback** 在浏览器空闲时分批解压：

- 一次只解压一个包，利用帧间空闲时间
- 不阻塞主线程，用户交互和渲染不受影响
- 做了兼容性处理：不支持 rIC 的浏览器用自实现的 polyfill

## Polyfill 原理（与 React Scheduler 一致）

```
rAF 获取每帧截止时间 → MessageChannel 在帧渲染后触发宏任务
    → 判断剩余时间是否充足 → 有空闲才执行回调
```

### 核心流程

1. `requestAnimationFrame` 拿到当前帧起始时间 + 16.6ms = 帧截止时间
2. 通过 `MessageChannel.postMessage` 在帧末尾插入一个**宏任务**
3. 宏任务中计算 `timeRemaining()`，有空闲才执行回调
4. 若已超时（`didTimeout`），也强制执行避免饿死

### 为什么用 MessageChannel 而不是 setTimeout？

- `setTimeout(fn, 0)` 在嵌套层级深时有 **4ms 最小延迟**限制
- `MessageChannel` 是纯粹的宏任务调度，无延迟下限，更精准

## 代码实现

```ts
const channel = new MessageChannel()
const activeFrameTime = 1000 / 60 // ≈16.6ms 每帧时长
let frameDeadline: number          // 当前帧截止时间
let pendingCallback: ((deadline: IdleDeadline) => void) | null

const timeRemaining = () => frameDeadline - performance.now()

// 监听 port2 → 帧末尾宏任务触发
channel.port2.onmessage = () => {
  const currentTime = performance.now()
  const didTimeout = frameDeadline <= currentTime

  if (didTimeout || timeRemaining() > 0) {
    pendingCallback?.({ didTimeout, timeRemaining })
  }
}

export const myRequestIdleCallback = (
  callback: (deadline: IdleDeadline) => void,
  _options?: IdleRequestOptions
) => {
  requestAnimationFrame(rafTime => {
    // 帧起始时间 + 16.6ms = 帧截止时间
    frameDeadline = rafTime + activeFrameTime
    pendingCallback = callback
    // postMessage 插入宏任务，等帧渲染完再执行
    channel.port1.postMessage('run')
  })
}
```

## 效果

优化后地图初始化流畅度明显提升，15 个压缩包的分批解压对用户无感知。
