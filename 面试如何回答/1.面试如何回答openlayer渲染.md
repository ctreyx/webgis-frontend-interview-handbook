 
# 天气地图肯定涉及到大量的气象数据渲染，比如风场、温度场、降水云图这些。我想问的是——你们的天气数据（比如风场数据）是什么格式的？前端拿到数据后是怎么渲染成风场动画的？是自己用 Canvas / WebGL 手写 的，还是用了第三方库？如果数据量很大的情况下，你做过哪些性能优化？



第一，数据格式层面，气象数据一般是 GRIB2 或者后端解析好的 JSON 格点数据（每个格点包含经纬度 + U/V 分量或标量值）。

第二，风场渲染原理，不管用什么库，风场动画的核心原理基本都是——在 Canvas 上随机撒粒子，每一帧根据格点数据插值算出粒子当前位置的风速风向，然后移动粒子，加上拖尾效果形成流线。这个你应该要能说出来。

第三，性能优化，连续场数据真正的优化手段应该包括：

1. 降采样：后端或前端对格点数据做抽稀，降低分辨率
2. 粒子数量控制：根据视口缩放等级动态调整粒子数
3. 离屏 Canvas：双 Canvas 方案，一个绘制一个合成
4. WebGL 替代 Canvas2D：大数据量下用 GPU 加速
5. 视口裁剪：只渲染当前可视范围内的格点

 

 我们后端给的数据是json，数据结构是起始经纬度，data数组，XY轴的间隔，然后计算每个经纬度的值。  渲染效果是用OE，基本原理就是每个经纬度格点计算出值大小，根据色表图填制渲染。 如果数据太大，性能优化，一般采用 抽稀值，根据视图窗口裁剪渲染当前视口。
 OE 底层已经做了视口裁剪和按层级抽稀的处理，我看过它的源码，核心是在 postrender 事件里只对当前 extent 范围内的格点做计算。在我们的业务场景下数据量级大概是 XXX 个格点，目前性能是够用的，没有出现明显瓶颈。但如果未来数据量再上一个量级，我会考虑用 WebGL 方案替代 Canvas2D，或者用 Web Worker 把插值计算放到后台线程。
