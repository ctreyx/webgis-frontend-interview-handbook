# 你有什么想问我的吗


有三个问题想请教一下：

第一，咱们团队目前 GIS 项目的技术栈是怎样的？当前最大的技术挑战是什么？我想了解一下，看看我之前的经验能不能直接用上。

第二，前端团队目前多少人？有没有 Code Review 或者技术分享的机制？我个人比较看重团队的技术氛围，因为我觉得好的团队能互相拉高上限。

第三，如果我有幸加入，前三个月您对我的期望是什么？有没有希望我优先承担的项目？我想提前了解，入职前可以做一些针对性的准备。





第一个问题，关于技术现状。

咱们目前 GIS 项目的前端架构是怎样的？我想了解几个维度：地图引擎用的是 Cesium 还是其他的？渲染层有没有做过性能优化？前端构建用的 Webpack 还是 Vite？有没有公共组件库或者技术文档沉淀？

我问这个不是挑毛病，而是我过去 8 年每次进一个新团队，第一件事就是摸清技术现状，找到投入产出比最高的优化点。

比如我之前进团队发现首屏加载 4 秒，花两周优化到 2 秒，立竿见影。如果咱们项目也有类似的痛点，我希望入职第一个月就能拿出成果，而不是花三个月熟悉业务才开始产出。所以我需要提前了解现状，判断我来了之后第一刀应该切在哪里。

第二个问题，关于团队和协作。

前端团队目前多少人？技术水平大概是什么层次？有没有已经建立的代码规范、Code Review 机制、或者技术分享制度？

我问这个是因为，我对自己的定位不只是一个写代码的人。如果团队目前还没有这些机制，这恰恰是我能快速带来价值的地方——我之前搭建过 ESLint + Husky + commitlint 的工程化规范，也建立过 Code Review 流程。这些东西前期投入一周，后期每个迭代帮团队省两三天，而且代码质量会有质的提升。

但如果团队已经有很成熟的机制了，那我的价值就应该放在其他地方，比如攻克技术难点或者做架构升级。 所以我需要了解团队现状来判断我的精力应该优先投在哪里。

第三个问题，关于业务方向。

咱们 GIS 项目未来半年到一年的业务规划是什么方向？是继续做气象可视化，还是会往智慧城市、数字孪生这些方向扩展？数据量级会不会有大的增长？

我问这个是因为不同的业务方向，前端架构的设计思路是完全不同的。如果数据量级要翻倍增长，现在就要考虑 Web Worker 多线程架构和数据分片加载策略，不能等到数据量上来了再补，那时候改架构的成本是现在的十倍。

我希望做的不是来了之后被动接需求，而是提前了解业务方向，在架构层面做好准备，等业务扩展的时候技术架构能无缝承接，不会成为瓶颈。

最后一个问题，比较直接。

如果我有幸通过面试，您希望我入职后前三个月优先解决什么问题？有没有目前团队想做但一直没有人手或能力去做的事情？

我问这个不是客套，是我真的想知道——团队现在最疼的那个点是什么。 如果我来了第一件事就是解决团队最疼的问题，这是建立信任最快的方式。我不想花三个月慢慢融入，我希望第一个月就让团队感受到'这个人来了，确实不一样'。"
