# 如果要多任务优先级，如何设计

## 核心思路

我最初的设计是多队列按优先级分组，但遍历找过期任务是 O(n)。更好的方案是参考 React Scheduler，用最小堆按 expirationTime 排序，堆顶永远是最紧急的任务，取任务和插入任务都是 O(log n)，不管任务量多大都不会影响调度性能。

## 为什么用最小堆（对比栈）

```text
┌──────────────────────────────────────────────────────┐
│  栈（你理解的方式）：                                  │
│                                                       │
│  [100ms, 250ms, 500ms, 1s, 5s]  → 新任务加后面       │
│                                                       │
│  问题：如果新来一个 50ms 的任务                        │
│  [100ms, 250ms, 500ms, 1s, 5s, 50ms]                │
│  堆顶还是 100ms，50ms 排在最后面！                     │
│  50ms 的任务反而最后执行，完全错误 ❌                  │
│                                                       │
└──────────────────────────────────────────────────────┘
```

```text
┌──────────────────────────────────────────────────────┐
│  最小堆（正确的方式）：                                │
│                                                       │
│  新任务插入时，会自动"上浮"到正确位置                  │
│                                                       │
│  第一步：先插入到最后                                  │
│  [100ms, 250ms, 500ms, 1s, 5s, 50ms]                │
│                                                       │
│  第二步：50ms 和父节点比较                             │
│  父节点是 500ms，50ms < 500ms → 交换                  │
│  [100ms, 250ms, 50ms, 1s, 5s, 500ms]                │
│                                                       │
│  第三步：继续和父节点比较                              │
│  父节点是 100ms，50ms < 100ms → 交换                  │
│  [50ms, 250ms, 100ms, 1s, 5s, 500ms]                │
│                                                       │
│  第四步：50ms 到了堆顶，没有父节点了，停止             │
│  堆顶永远是最小的 ✅                                   │
│                                                       │
└──────────────────────────────────────────────────────┘
```

## 代码实现

```js
class MinHeap {
  constructor() {
    this.heap = []
  }

  // 插入任务，自动上浮到正确位置
  push(task) {
    this.heap.push(task)
    this.bubbleUp()        // 上浮
  }

  // 取堆顶（最紧急的任务）
  pop() {
    const top = this.heap[0]
    const last = this.heap.pop()
    if (this.heap.length > 0) {
      this.heap[0] = last
      this.sinkDown()      // 下沉，重新排列
    }
    return top
  }

  // 只看堆顶，不取出
  peek() {
    return this.heap[0]
  }
}

// 使用
const scheduler = new MinHeap()

scheduler.push({ callback: task1, expirationTime: 1000 })
scheduler.push({ callback: task2, expirationTime: 50 })   // 插入后自动到堆顶
scheduler.push({ callback: task3, expirationTime: 500 })

scheduler.peek()  // 自动返回 expirationTime=50 的任务
scheduler.pop()   // 取出后堆自动重新排列
```

## 面试中完整话术

我们 Cesium 项目有大量 CPU 密集型任务，比如雷达数据解压、格点计算，直接在主线程执行会导致地图交互卡顿。我自研了一个通用的空闲任务调度器，核心是 rAF + MessageChannel 做时间切片，每帧检查剩余时间，有空闲才执行任务。

任务管理参考了 React Scheduler 的架构，用最小堆按 expirationTime 排序，取任务是 O(log n) 不需要遍历。支持四级优先级，通过过期时间解决低优先级任务饥饿问题。维护 taskQueue 和 timerQueue 双堆，已过期的优先执行，未过期的等待到期。

最终封装成 Vue3 的 composable，绑定 onUnmounted 自动清理。实际用在雷达解压场景，15 个压缩包空闲分批解压，地图交互全程流畅。"
