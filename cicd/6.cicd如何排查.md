



流水线报错我会按三层排查：

第一层看报错日志。流水线的每个 stage 都有执行日志，90% 的问题看日志就能定位。比如之前 Node 版本的问题，日志直接报 node command not found，一看就知道是环境版本配置不对。

第二层区分是'代码问题'还是'环境问题'。如果同样的代码本地能跑通但 CI 报错，大概率是环境差异。比如 Cesium 的全局 ts 定义，本地 IDE 自动识别了，但 CI 环境是干净的，缺少全局类型定义就报错了。解决方式是在 tsconfig 里显式引入全局类型声明文件。

第三层看是不是外部依赖问题。比如 AI 审查依赖 DeepSeek API，如果 API 超时或者网络波动，流水线也会挂。这类问题不是代码的问题，所以我给 AI 审查阶段设了 allowFailure，API 异常不会阻断后续的构建和部署。
