规范上我要求小步提交、频繁合并，大部分情况下单次 MR 不会超过 500 行。但现实中确实有例外，比如大的重构或者新模块开发。

技术上我做了三层处理：

第一，过滤无关文件。AI 审查只看核心代码文件——.vue、.ts、.tsx，自动排除 lock 文件、dist 目录、类型声明文件、自动生成的代码。这样实际需要审查的 diff 量会大幅减少。

第二，按文件拆分审查。如果过滤后 diff 仍然超过 LLM 上下文窗口，我不会简单截断，而是按文件拆分——每个文件的 diff 单独发给 LLM 审查一次，最后汇总所有文件的审查结果。这样不会漏检。

第三，兜底截断 + 提示。如果单个文件的 diff 就超过了上下文窗口（极端情况），才做截断，并且在审查报告里标注'该文件 diff 过大，只审查了前 N 行，建议人工补充审查'。"
