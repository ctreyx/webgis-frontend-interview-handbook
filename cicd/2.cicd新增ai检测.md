# AI 接入 CI/CD 验证：完整方案

## 面试时如果被问到这类问题，你可以这样回答

> *"我理解企业想在 CI/CD 里接入 AI，一般是想解决传统规则检查覆盖不到的场景。我会分几类考虑：*
>
> *第一类是 AI Code Review，在 MR 阶段把 diff 发给 LLM，做逻辑合理性、安全隐患、最佳实践的语义审查，这是规则工具（ESLint）做不到的，因为 ESLint 只能查语法层面的问题。*
>
> *第二类是如果项目本身是 AI 应用，比如我做的文旅 Agent，流水线里会加评测门禁——每次改动 prompt 或参数，自动跑 RAGAS 评测集，Faithfulness、Context Recall 这些指标不达标就阻断部署，防止带着质量问题上线。*
>
> *落地上要注意几个点：*
>
> *第一，AI 判断有不确定性，不能直接用来'一票否决'阻断流水线，一般是先做 WARNING 级别提示，观察一段时间准确率之后再考虑要不要做硬性阻断。*
>
> *第二，要控制调用成本和延迟，每次 push 都调 LLM 审查，如果 diff 很大，延迟和费用会上升，需要考虑只审查改动的核心文件，或者设置触发条件（比如只在 MR 到 main 分支时触发，不是每次 push 都触发）。*
>
> *第三，需要一个反馈机制收集 AI 判断的误判案例，持续优化审查 prompt，这个思路和我在 RAG 项目里做的评测迭代是一致的——用真实案例不断修正规则。"*

## 先想清楚：企业为什么想在 CI/CD 里接入 AI

传统 CI/CD 只能做**规则匹配式**的检查——ESLint 检查语法、单元测试检查已知场景。但有些问题规则查不出来：

| 传统 CI/CD 查不出的问题 | AI 能查什么 |
|----------------------|-----------|
| 代码逻辑是否合理，即使语法正确 | Code Review 类的语义分析 |
| Commit message 写得是否清晰 | 自动生成/校验 commit 质量 |
| PR 改动是否有安全隐患 | 安全漏洞语义扫描 |
| 单元测试覆盖率够但测试用例质量差 | AI 生成额外的边界测试用例 |
| AI 应用本身生成内容的质量 | 你项目里的 RAGAS 评测 |

---

## 企业接入 AI 到 CI/CD 通常做的几类事情

---

### 类型一：AI Code Review（最常见）

流水线里加一步，把 diff 发给 LLM，让它做代码审查：

```yaml
ai-review:
  stage: check
  script:
    - python ai_review.py --diff $(git diff origin/main...HEAD)
```

```python
# ai_review.py 大致逻辑
diff = get_git_diff()

prompt = f"""你是资深代码审查专家，请审查以下代码变更：

{diff}

请检查：
1. 是否有明显的逻辑错误
2. 是否有安全隐患（SQL注入、XSS、密钥泄露）
3. 是否符合最佳实践
4. 命名是否清晰

如果发现严重问题，返回 BLOCK；如果只是建议，返回 WARNING；都没问题返回 PASS。
"""

result = llm.invoke(prompt)

if "BLOCK" in result:
    print("❌ AI 审查发现严重问题，阻断合并")
    exit(1)
```

**这类工具已经有商业化产品**，比如 CodeRabbit、Copilot 的 PR Review 功能，很多企业直接接第三方服务，而不是自己写。

---

### 类型二：AI 生成测试用例并校验覆盖率

```yaml
ai-test-gen:
  stage: test
  script:
    - python ai_generate_tests.py --changed-files
    - npm run test
```

流程：

```
检测本次 diff 改动了哪些函数
    ↓
把函数代码喂给 LLM
    ↓
LLM 生成对应的单元测试用例（边界值、异常场景）
    ↓
自动跑这些测试
    ↓
如果新生成的测试都过不了，说明代码可能有问题
```

---

### 类型三：AI 应用自身的质量门禁（你已经做的这类）

这是你项目里 RAGAS 那套的思路，企业如果做 AI 应用（不是普通前端项目），流水线里会加：

```yaml
llm-quality-gate:
  stage: evaluate
  script:
    - python evaluate.py --n 50
    - python check_scores.py   # 分数不达标就 exit(1)
```

---

### 类型四：AI 辅助生成 Commit Message / Changelog

```yaml
generate-changelog:
  stage: post-merge
  script:
    - python ai_changelog.py --commits $(git log --oneline main..HEAD)
```

让 LLM 根据 commit 记录自动生成人类可读的更新日志。

---

### 类型五：AI 做安全扫描（更前沿）

结合传统安全扫描工具（如 Semgrep）+ LLM 做语义层面的二次判断，减少误报：

```
Semgrep 规则扫描 → 发现 100 个"可能的"问题
        ↓
LLM 逐条判断是否是真正的安全隐患
        ↓
过滤后只剩 5 个真正需要人工看的问题
```
