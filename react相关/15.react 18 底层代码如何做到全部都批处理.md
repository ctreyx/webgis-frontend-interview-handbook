# react 18 底层代码如何做到全部都批处理



**一句话总结：React 18 的 setState 永远不会立即渲染，而是把更新注册到一个 lane 里，然后通过微任务统一调度。所有同步代码执行完之后，微任务才触发，自然就把所有 setState 合并了。**

## 面试标准回答

> "React 17 的批处理靠的是一个同步的开关变量 `isBatchingUpdates`。React 在自己的合成事件里会手动开关这个变量，所以事件函数里的 setState 能被批处理。但 setTimeout、Promise 这些异步回调执行时，开关已经关了，React 控制不到，所以每次 setState 都会同步渲染。
>
> React 18 把机制从'同步开关'改成了'微任务调度'。每次 setState 不再直接渲染，而是把更新挂到 fiber 上，然后调用 `ensureRootIsScheduled`。这个函数会检查是否已经注册过调度任务，如果没有就通过 `queueMicrotask` 注册一个微任务，如果已经注册了就直接返回。因为微任务一定在所有同步代码执行完之后才触发，所以不管你在哪里调多少次 setState，微任务执行时一定能收集到所有更新，一次性处理。
>
> 另外 React 18 的 Lane 模型也起了作用——用二进制位运算天然合并同优先级的更新，同一个 lane 的多次更新只需要处理一次。
>
> 所以 React 18 的自动批处理不是'加了个更大的 try-finally'，而是从根本上改变了调度模型——从同步执行变成了微任务延迟执行。"

## 核心问题：React 17 为什么做不到全局批处理？

### React 17 的批处理机制：一个开关变量

```typescript
// React 17 简化后的核心逻辑
let isBatchingUpdates = false  // 全局开关

// React 合成事件的入口
function dispatchEvent(event) {
  isBatchingUpdates = true      // ① 进入事件前，打开开关

  try {
    handler(event)               // ② 执行你的事件处理函数
    // 你的 setState 都在这里面调用
    // 因为开关是 true，所以 setState 不会立即渲染
    // 而是把更新放进队列
  } finally {
    isBatchingUpdates = false    // ③ 事件结束，关闭开关
    flushSyncUpdates()           // ④ 一次性处理队列里所有更新
  }
}

// setState 的核心逻辑
function setState(update) {
  queue.push(update)             // 放入更新队列

  if (isBatchingUpdates) {
    // 开关开着 → 什么都不做，等 flushSyncUpdates 统一处理
    return
  } else {
    // 开关关着 → 立即同步渲染！
    renderImmediately()
  }
}
```

**问题出在哪？**

```typescript
const handleClick = () => {
  // 此时 isBatchingUpdates = true（React 合成事件控制的）
  setState(1)  // 进队列，不渲染 ✅
  setState(2)  // 进队列，不渲染 ✅
  setState(3)  // 进队列，不渲染 ✅

  setTimeout(() => {
    // 此时 isBatchingUpdates = false ！！！
    // 因为 setTimeout 的回调是在"事件处理结束之后"才执行的
    // 那时候 finally 已经把开关关了

    setState(4)  // 开关关着 → 立即渲染 ❌
    setState(5)  // 开关关着 → 立即渲染 ❌
  })
}
```

**根本原因：React 17 用同步的开关变量来控制批处理，但 setTimeout / Promise 的回调执行时，开关已经关了，React 无法包裹这些异步代码。**

## React 18 怎么解决的？

### 核心改变：从"同步开关"变成"微任务调度"

**一句话总结：React 18 的 setState 永远不会立即渲染，而是把更新注册到一个 lane 里，然后通过微任务统一调度。所有同步代码执行完之后，微任务才触发，自然就把所有 setState 合并了。**

---

### 第一层：setState 不再直接渲染

```typescript
// React 18 简化后的 setState
function dispatchSetState(fiber, queue, action) {
  // ① 创建一个 update 对象
  const update = {
    action,      // 你传的新值或更新函数
    lane,        // 优先级（后面讲）
    next: null,
  }

  // ② 把 update 挂到 fiber 的更新队列上
  enqueueUpdate(fiber, update)

  // ③ 调度一次渲染（但不是立即渲染！）
  scheduleUpdateOnFiber(fiber, lane)
}
```

关键在 `scheduleUpdateOnFiber`：

```typescript
function scheduleUpdateOnFiber(fiber, lane) {
  // ① 把这个 lane 标记到 root 上
  // lane 就是一个二进制位，表示"有一个待处理的更新"
  root.pendingLanes |= lane

  // ② 确保 root 被调度
  ensureRootIsScheduled(root)
}
```

---

### 第二层：ensureRootIsScheduled —— 关键中的关键

```typescript
// 这个函数是 React 18 自动批处理的核心
function ensureRootIsScheduled(root) {
  // ① 检查是否已经调度过了
  if (root.callbackNode !== null) {
    // 已经有一个待执行的调度任务了，不需要重复调度
    // 直接返回！！！
    return
  }

  // ② 还没调度过，创建一个微任务来处理所有更新
  // React 18 用的是 queueMicrotask（或 MessageChannel 降级）
  const callback = () => {
    performConcurrentWorkOnRoot(root)
  }

  // 注册微任务
  scheduleMicrotask(callback)

  // 记录下来，防止重复调度
  root.callbackNode = callback
}
```

**这就是魔法所在：**

```typescript
const handleClick = () => {
  setTimeout(() => {
    setA(1)
    // → dispatchSetState → scheduleUpdateOnFiber → ensureRootIsScheduled
    // → 第一次调用，root.callbackNode 为空
    // → 注册一个微任务
    // → 函数返回，继续执行下面的代码

    setB(2)
    // → dispatchSetState → scheduleUpdateOnFiber → ensureRootIsScheduled
    // → root.callbackNode 已经有了！
    // → 直接 return，不重复注册 ✅

    setC(3)
    // → 同上，直接 return ✅

    // 同步代码全部执行完毕

    // ---- 微任务开始执行 ----
    // performConcurrentWorkOnRoot(root)
    // 此时 root 上有 A、B、C 三个 pending update
    // 一次性处理，只渲染一次 ✅
  })
}
```

### 第三层：为什么微任务能实现批处理？

这是 JavaScript 事件循环的特性：

```
┌─────────────────────────────────────────────────┐
│              一次事件循环                         │
│                                                  │
│  1. 宏任务（setTimeout 回调）                     │
│     ├── setA(1) → 注册微任务                     │
│     ├── setB(2) → 已注册，跳过                   │
│     └── setC(3) → 已注册，跳过                   │
│                                                  │
│  2. 微任务队列（同步代码执行完后立即执行）          │
│     └── performConcurrentWorkOnRoot()            │
│         → 读取所有 pendingLanes                  │
│         → 处理 A、B、C 三个更新                   │
│         → 只渲染一次                             │
│                                                  │
│  3. 浏览器渲染                                   │
│     └── 只绘制一帧                               │
│                                                  │
└─────────────────────────────────────────────────┘
```

**同步代码一定在微任务之前全部执行完。所以不管你在同步代码里调用多少次 setState，微任务触发时一定能拿到所有更新。**

---

### 第四层：Lane 模型（优先级系统）

React 18 不只是批处理，还引入了优先级。Lane 是一个二进制位：

```typescript
// 简化版 Lane 定义
const SyncLane         = 0b0000000000000000000000000000001  // 同步（最高优先级）
const InputContinuous  = 0b0000000000000000000000000000100  // 连续输入（拖拽等）
const DefaultLane      = 0b0000000000000000000000000010000  // 默认（setState）
const IdleLane         = 0b0100000000000000000000000000000  // 空闲（最低优先级）
```

```typescript
function scheduleUpdateOnFiber(fiber, lane) {
  // 用位运算合并多个 lane
  root.pendingLanes |= lane

  // 比如三次 setState 都是 DefaultLane：
  // pendingLanes = 0b000...10000
  //              | 0b000...10000
  //              | 0b000...10000
  //              = 0b000...10000  （还是同一个 lane）
  // 所以只需要处理一次

  ensureRootIsScheduled(root)
}
```

**位运算天然具有"合并"能力**——同优先级的多次更新合并成一个 lane，一次处理。

```

    ▼

    │  创建 update 对象，挂到 fiber 上
    ▼

    │  root.pendingLanes |= lane
    ▼

    │  root.callbackNode === null ?
    │
    ├── 是 → scheduleMicrotask(performWork)
    │        设置 root.callbackNode
    │        返回
    │
    └── 否 → 直接返回（已调度过了）

setState(2) → 同上 → ensureRootIsScheduled → 已调度，返回
setState(3) → 同上 → ensureRootIsScheduled → 已调度，返回

... 同步代码全部执行完 ...

微任务执行：
performConcurrentWorkOnRoot(root)
    │  读取 root.pendingLanes
    │  找到所有 pending update
    ▼
processUpdateQueue()
    │  遍历 fiber 上的 update 链表
    │  依次计算新 state
    ▼
reconcileChildren()  →  commitRoot()
    │                      │
    生成新的 Fiber 树        一次性更新 DOM
    (只遍历一次)             (只渲染一帧)
```

## React 17 vs 18 的核心代码对比

```typescript
// ========== React 17 ==========
// 依赖同步开关变量

let isBatchingUpdates = false

function batchedUpdates(fn) {
  isBatchingUpdates = true   // 手动开
  fn()
  isBatchingUpdates = false  // 手动关
  flushUpdates()             // 手动刷
}

// React 只在自己的事件系统里调用 batchedUpdates
// setTimeout/Promise 里的代码不在 batchedUpdates 里
// 所以不会被批处理


// ========== React 18 ==========
// 依赖微任务调度

function ensureRootIsScheduled(root) {
  if (root.callbackNode) return  // 已调度就跳过

  // 用微任务延迟执行，等所有同步 setState 都入队
  scheduleMicrotask(() => {
    performConcurrentWorkOnRoot(root)
    root.callbackNode = null  // 执行完清空，允许下次调度
  })

  root.callbackNode = true
}

// 不管 setState 在哪里调用（事件/setTimeout/Promise/原生事件）
// 都走同一个 ensureRootIsScheduled
// 都会被微任务收集到一起批量处理
```
