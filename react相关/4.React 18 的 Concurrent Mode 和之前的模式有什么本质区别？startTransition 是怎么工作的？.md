# React 18 的 Concurrent Mode 和之前的模式有什么本质区别？startTransition 是怎么工作的？

Concurrent Mode 与 startTransition
本质区别：可中断 vs 不可中断

React 17 之前（Legacy Mode）：同步不可中断

JS Main Thread:
├── setState 触发
├──────────────────────────────── render 开始
│ reconcile fiber A
│ reconcile fiber B
│ reconcile fiber C ← 用户点击！但必须等我渲染完
│ reconcile fiber D
│ ...（可能几十毫秒）
├──────────────────────────────── commit
└── 用户交互响应 ← 用户早就不耐烦了

React 18 Concurrent Mode：异步可中断

JS Main Thread:
├── setState 触发
├── reconcile fiber A ← 每个 fiber 完成后检查：有更高优先级任务吗？
├── [检查] 有用户输入！暂停当前渲染！ 
├──────── 处理用户输入（高优先级）
├──────── 输入处理完成
├── reconcile fiber B ← 从暂停处继续（或从头重来）
├── reconcile fiber C
└── commit

# Concurrent Mode 三大核心能力：

┌────────────────────────────────────────────────────────┐
│ 1. 可中断渲染（Interruptible Rendering） │
│ Render 阶段可暂停/继续/丢弃 │
│ Commit 阶段仍然同步（DOM 操作不可中断） │
│ │
│ 2. 优先级调度（Priority Scheduling） │
│ 基于 Lane 模型，高优先级任务插队 │
│ 用户交互 > 数据更新 > 后台预渲染 │
│ │
│ 3. 并发特性解锁 │
│ startTransition：标记低优先级更新 │
│ useDeferredValue：延迟派生值 │
│ Suspense + streaming SSR │
└────────────────────────────────────────────────────────┘
