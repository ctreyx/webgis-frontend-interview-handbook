


React 一次状态更新大概分成调度、render、commit 三个阶段。

1. 首先调用 setState  时，React 不会立刻更新 DOM，而是创建一个 update 对象，把它挂到当前 Fiber 的 updateQueue 上。对于 Hooks 来说，会挂到对应 Hook 的 queue 上；对于 class 组件，会挂到 Fiber 的 updateQueue 上。

2. 然后 React 会根据当前更新的来源分配一个 lane，也就是更新优先级。比如用户输入、点击这种交互优先级更高，普通异步更新优先级更低。接着 React 会从当前 Fiber 一直向上找到 root，标记这条路径上有哪些 lane 需要更新，并通过 Scheduler 调度这次任务。

进入 render 阶段后，React 会基于 current Fiber 树创建一棵 workInProgress Fiber 树。这个阶段会执行 beginWork 和 completeWork。

3. beginWork 主要负责处理当前 Fiber：比如执行函数组件、计算子节点、做 reconciliation，判断哪些子 Fiber 可以复用，哪些需要新增、删除或更新。

4. completeWork 主要是向上归并结果：比如 mount 阶段创建 DOM 节点，update 阶段准备更新 payload，同时收集 flags 和 subtreeFlags。

render 阶段本质上是计算阶段，它不会真正操作 DOM。在 Concurrent 模式下，这个阶段是可以被打断和恢复的。

5. 当整棵 workInProgress 树构建完成后，React 进入 commit 阶段。commit 阶段是同步不可中断的，主要负责把 render 阶段计算出来的变化真正提交到宿主环境，也就是更新真实 DOM。

6. commit 阶段可以分为 beforeMutation 、mutation、layout 三部分：mutation 阶段真正操作 DOM，layout 阶段执行 useLayoutEffect 和生命周期，useEffect 这类 passive effect 会在 commit 后异步调度。

最后 React 会把 finishedWork 切换成新的 current tree。之后浏览器再基于真实 DOM 的变化进行 layout 和 paint。

React 之所以分 render 和 commit，是因为 render 阶段是纯计算，可以被打断、让出主线程和做优先级调度；commit 阶段涉及真实 DOM 和副作用，必须一次性同步完成，不能中断，否则页面会处于不一致状态。
