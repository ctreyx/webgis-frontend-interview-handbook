# useEffect 和 useLayoutEffect 的区别

> 从 Commit 阶段三个子阶段的角度解释：它们分别在哪个子阶段执行？为什么 useLayoutEffect 会阻塞浏览器渲染？

---

## 一、Commit 阶段的完整流程

`
render 阶段（可中断）
       ↓
 beforeMutation 阶段
       ↓
   mutation 阶段
       ↓
   layout 阶段
       ↓
 浏览器 Paint  浏览器接管：Style → Layout → Paint → Composite
       ↓
useEffect 异步执行
`

---

## 二、两个 Hook 的执行时机对比

| Hook | 执行时机 | 对应子阶段 |
|---|---|---|
| useLayoutEffect 清除函数 | DOM 变更前 | mutation 阶段 |
| useLayoutEffect 回调 | DOM 变更完成后，Paint 之前 | layout 阶段 |
| useEffect | 浏览器 Paint 之后 | commit 结束后**异步**调度 |

---

## 三、三个子阶段详解

### 1. eforeMutation 阶段

| 维度 | 说明 |
|---|---|
| **做什么** | 读取 DOM 快照，准备变更 |
| **对应 Hook** | getSnapshotBeforeUpdate（Class 组件） |
| **特点** | DOM 还没变，可以读取变化前的 DOM 状态 |

### 2. mutation 阶段

| 维度 | 说明 |
|---|---|
| **做什么** | 真正执行 DOM 增删改 |
| **对应 Hook** | useLayoutEffect 的**清除函数**在此执行 |
| **特点** | 真实 DOM 操作发生的地方，flags 标记在这里被消费 |

### 3. layout 阶段

| 维度 | 说明 |
|---|---|
| **做什么** | DOM 操作完成后，执行副作用回调 |
| **对应 Hook** | useLayoutEffect 回调、componentDidMount、componentDidUpdate |
| **特点** | **同步执行**，浏览器还没 Paint，此时操作 DOM 不会触发额外回流 |

---

## 四、为什么 useLayoutEffect 会阻塞浏览器渲染？

- useLayoutEffect 在 **layout 阶段同步执行**
- JS 线程和 GUI 渲染线程**互斥**（浏览器单线程模型）
- layout 阶段没执行完 → 浏览器**不能进入 Paint**
- 所以 useLayoutEffect 里如果有耗时操作 → **直接阻塞页面渲染** → 用户看到白屏或卡顿

> **总结：useLayoutEffect = 同步阻塞 Paint，useEffect = Paint 后异步执行，不阻塞渲染。**
