# Fiber 可中断机制 —— 源码级拆解

> 在 reconcile 阶段，React 是怎么通过 Fiber 链表实现"可中断"的？具体的中断和恢复机制是什么？


总结：在 workloopconcurrent 中，不中断while检查 当前是否有 workinprogress 和  shouldYield ，如果有，进入单元处理 performunitofwork 不断向下处理节点，返回child ，如果没有 child 则进入completeunitofwork 代表结束， 如果有，则更新 workInProgress ，会再次进入workloopconcurrent

---

## 一、核心入口：`workLoopConcurrent`

```js
// react-reconciler/src/ReactFiberWorkLoop.js

function workLoopConcurrent() {
  // 关键：每次循环都检查 shouldYield()
  while (workInProgress !== null && !shouldYield()) {
    performUnitOfWork(workInProgress);
  }
}

// 对比同步模式，没有 shouldYield 判断，不可中断
function workLoopSync() {
  while (workInProgress !== null) {
    performUnitOfWork(workInProgress);
  }
}
```

这里就是中断的核心：`shouldYield()` 是 Scheduler 暴露的方法，它会判断当前时间切片是否用完（通常 5ms）。如果用完了，while 循环直接退出，`workInProgress` 指针就停在当前 Fiber 节点上，不会丢失。

---

## 二、单元处理：`performUnitOfWork`

```js
function performUnitOfWork(unitOfWork) {
  const current = unitOfWork.alternate;

  // ① 向下：beginWork 处理当前节点，返回 child
  let next = beginWork(current, unitOfWork, renderLanes);

  if (next === null) {
    // ② 没有 child 了，进入 completeUnitOfWork
    completeUnitOfWork(unitOfWork);
  } else {
    // ③ 有 child，workInProgress 指向 child，继续下一轮 while
    workInProgress = next;
  }
}
```

---

## 三、回溯过程：`completeUnitOfWork`

```js
function completeUnitOfWork(unitOfWork) {
  let completedWork = unitOfWork;

  do {
    const current = completedWork.alternate;
    const returnFiber = completedWork.return;  // 父节点

    // 完成当前节点的工作（创建/更新 DOM 实例，收集 flags）
    completeWork(current, completedWork, renderLanes);

    // 有兄弟节点 → 返回给 workInProgress，进入兄弟的 beginWork
    const siblingFiber = completedWork.sibling;
    if (siblingFiber !== null) {
      workInProgress = siblingFiber;
      return;  // 退出 completeUnitOfWork，回到 while 循环
    }

    // 没有兄弟 → 继续向上回溯到父节点
    completedWork = returnFiber;
    workInProgress = completedWork;

  } while (completedWork !== null);
}
```

---

## 四、中断与恢复的本质

假设在处理完某个节点之后，时间切片用完了：

```
shouldYield() === true
→ while 循环退出
→ workInProgress 停在当前节点
→ 控制权交还浏览器（渲染、用户事件等）
→ 下一个 MessageChannel 回调触发
→ 从当前节点继续执行，完全不需要从头开始
```

这就是"中断与恢复"的本质——**`workInProgress` 指针就是书签**。

## 五、`shouldYield` 的实现

```js
// scheduler/src/Scheduler.js

function shouldYieldToHost() {
  const currentTime = getCurrentTime();
  // deadline = startTime + 5ms（yieldInterval）
  if (currentTime >= deadline) {
    // 时间片用完
    return true;
  }
  return false;
}
```
