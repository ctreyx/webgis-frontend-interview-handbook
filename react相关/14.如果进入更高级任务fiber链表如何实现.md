# 高优先级任务抢占 —— 源码链路

## 一句话总结

> 高优先级进来 → `cancelCallback` 取消当前调度 → `prepareFreshStack` 丢弃半成品 → 从 root 用高优先级重新 reconcile → commit 上屏 → 回头再调度低优先级从头再来。
>
> 所以低优先级的工作不是暂停恢复，而是**直接丢弃重做**。这也是为什么 React 官方一直强调 render 阶段必须是纯函数、无副作用的原因——因为它可能执行多次。

---

## 一、优先级从哪来？

React 用 **Lanes 模型**表示优先级，本质是二进制位运算：

```js
// react-reconciler/src/ReactFiberLane.js

const SyncLane            = 0b0000000000000000000000000000010;  // 最高：同步
const InputContinuousLane  = 0b0000000000000000000000000001000;  // 用户输入（拖拽等）
const DefaultLane          = 0b0000000000000000000000000100000;  // 默认（setState）
const IdleLane             = 0b0100000000000000000000000000000;  // 最低：空闲
```

位越低，优先级越高。比如你正在处理一个 `IdleLane` 的任务，用户突然点击按钮触发了 `SyncLane` 的更新。

---

## 二、新更新进来：`ensureRootIsScheduled`

任何 `setState` / `dispatch` 最终都会走到这里：

```js
// react-reconciler/src/ReactFiberRootScheduler.js

function ensureRootIsScheduled(root) {
  // ① 拿到当前 root 上所有待处理的 lanes，取最高优先级
  const nextLanes = getNextLanes(
    root,
    root === workInProgressRoot ? workInProgressRootRenderLanes : NoLanes
  );

  // ② 拿到正在进行的调度任务优先级
  const existingCallbackPriority = root.callbackPriority;
  const newCallbackPriority = getHighestPriorityLane(nextLanes);

  // ③ 关键判断：新任务优先级 === 正在调度的优先级 → 复用，不打断
  if (existingCallbackPriority === newCallbackPriority) {
    return; // 优先级一样，不需要重新调度
  }

  // ④ 新优先级更高！取消当前正在调度的任务
  if (existingCallbackNode != null) {
    cancelCallback(existingCallbackNode);  // 👈 取消旧任务
  }

  // ⑤ 用新优先级重新调度
  const newCallbackNode = scheduleCallback(
    schedulerPriorityLevel,
    performConcurrentWorkOnRoot.bind(null, root)
  );

  root.callbackNode = newCallbackNode;
  root.callbackPriority = newCallbackPriority;
}
```

核心就在第 ④ 步：`cancelCallback` 把正在执行的低优先级任务取消了。

---

## 三、取消后怎么重新开始？`prepareFreshStack`

当新的高优先级任务开始执行 `performConcurrentWorkOnRoot` → `renderRootConcurrent` 时：

```js
function renderRootConcurrent(root, lanes) {
  // 判断：如果当前正在渲染的 root 或 lanes 变了
  // 说明优先级被抢占了，需要丢弃之前的工作
  if (workInProgressRoot !== root || workInProgressRootRenderLanes !== lanes) {
    prepareFreshStack(root, lanes);  // 👈 重置！
  }

  // 然后进入 workLoopConcurrent...
}
```

```js
function prepareFreshStack(root, lanes) {
  root.finishedWork = null;

  // 关键：从 root 重新创建 workInProgress
  // 之前低优先级做到一半的 Fiber 树直接丢弃
  workInProgress = createWorkInProgress(root.current, null);
  workInProgressRootRenderLanes = lanes;
}
```

> 低优先级做到一半的工作直接丢弃，从 root 重新开始构建。这就是为什么 reconcile 阶段不能有副作用——因为它可能被丢弃重来。
