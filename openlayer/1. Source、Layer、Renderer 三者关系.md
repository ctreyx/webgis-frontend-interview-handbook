# OpenLayers 中 Source、Layer、Renderer 三者关系

## 一句话理解

Source 负责“数据从哪里来”，Layer 负责“怎么展示这份数据”，Renderer 负责“如何把它画到屏幕上”。

## 三者职责对比

| 组件     | 职责                                                   | 关键类                                              |
| -------- | ------------------------------------------------------ | --------------------------------------------------- |
| Source   | 数据源抽象基类，负责数据获取、解析、缓存               | OSM, XYZ, VectorSource, TileWMS                     |
| Layer    | 栅格或矢量数据的视觉表达，组织展示属性（与数据源解耦） | TileLayer, VectorLayer, ImageLayer                  |
| Renderer | 把地理要素转为渲染指令并在帧阶段执行绘制               | CanvasVectorLayerRenderer, WebGLPointsLayerRenderer |

## 数据流完整路径（Source 到屏幕）

数据流完整路径:

① Source 获取数据
│ 网络请求（XHR/fetch）获取瓦片图片、GeoJSON、WMS 等
▼
② Source 解析 & 缓存
│ Format 解析器将原始数据解析为 Feature/Tile 对象
│ Source 内部缓存已加载的数据
▼
③ Layer 提供渲染参数
│ visibility / opacity / extent / z-index / style
▼
④ Map 构建 FrameState
│ 收集当前 View 状态(center/resolution/rotation)
│ 收集所有 Layer 的状态
▼
⑤ Renderer 准备帧 (prepareFrame)
│ 确定可见范围内需要渲染的数据
│ 对矢量数据：遍历 Feature → 应用 Style → 生成渲染指令
│ 对瓦片数据：确定需要的瓦片 → 排入 TileQueue
▼
⑥ Renderer 渲染帧 (renderFrame)
│ Canvas: 执行缓存的渲染指令 (moveTo/lineTo/drawImage...)
│ WebGL: 提交 GPU buffer 并调用 drawElements
▼
⑦ 合成输出到 <canvas> 元素
│ 按 z-index 顺序合成各图层
▼
⑧ 屏幕显示

## 渲染后端说明

OpenLayers 支持多种渲染后端（Canvas、WebGL、DOM），常见的是 Canvas 和 WebGL。

Canvas 渲染器：
CanvasVectorLayerRenderer 主要处理要素图层，通过指令缓存、批量坐标变换、按 z-index 分组等方式优化性能。

WebGL 渲染器：
提供 GPU 加速渲染。通常由针对不同数据类型的专用渲染器组成，并共享 WebGL 基础设施，以减少 CPU-GPU 传输并通过缓冲区管理与批量绘制提升吞吐。

默认用 Canvas，数据量大时切 WebGL 性能差距 10 倍以上
