# 4.为什么需要EPSG:4326转换EPSG:3857

## 原因：墨卡托投影后，瓦片是正方形，计算简单 用经纬度的话瓦片是矩形，计算复杂很多

```js
const coord = ol.proj.transform(
  [116.4, 39.9], // 北京的经纬度
  "EPSG:4326", // 源坐标系：WGS84 经纬度
  "EPSG:3857", // 目标坐标系：Web 墨卡托
);
// 结果: [12958752.7, 4852834.1] (单位: 米)
```

```js
你的数据:   EPSG:4326 经纬度坐标  [116.4°, 39.9°]
                                      │
                                      │  坐标系不匹配！
                                      ▼
地图引擎:   EPSG:3857 平面坐标系   需要 [米, 米] 形式的坐标
                                      │
                                      │  ol.proj.transform()
                                      ▼
转换结果:   [12958752.7, 4852834.1]   可直接在地图上定位
```

## 3.2 EPSG:4326 vs EPSG:3857 本质区别

26

当 OpenLayers 加载时，它会添加 EPSG:4326（WGS84 地理坐标）和 EPSG:3857（Web 或球面墨卡托，例如被 Bing Maps 或 OpenStreetMap 使用）的投影对象以及相关的转换函数。

| 特征     | EPSG:4326 (WGS84)            | EPSG:3857 (Web Mercator)                 |
| -------- | ---------------------------- | ---------------------------------------- |
| 本质     | 地理坐标系（Geographic CRS） | 投影坐标系（Projected CRS）              |
| 坐标单位 | 度（°）                      | 米（m）                                  |
| 坐标含义 | 经度/纬度（角度）            | 平面 X/Y（距离）                         |
| 形状     | 椭球面上的角度位置           | 平面上的直角坐标                         |
| 覆盖范围 | 全球 [-180, -90] ~ [180, 90] | 约 [-85.06°, 85.06°] 纬度范围            |
| 等角性   | 无（本身不是投影）           | 是（保角投影，局部形状正确）             |
| 面积失真 | 无                           | 两极严重失真（格陵兰看起来像非洲那么大） |
| 适合场景 | 数据存储/交换/GPS            | Web 地图显示/瓦片切割                    |
