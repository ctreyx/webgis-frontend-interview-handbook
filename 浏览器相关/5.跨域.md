# 跨域 + CORS 预检请求

跨域是浏览器的同源策略限制，不是服务器拒绝了请求，而是浏览器拦截了响应。CORS 是服务器告诉浏览器"我允许你跨域"的机制。

协议 域名 端口

# 跨域请求发出去了吗

常见误解：跨域 = 请求没发出去

真相：
简单请求：请求发出去了，服务器也处理了，返回了响应
但浏览器发现响应头没有 Access-Control-Allow-Origin
→ 浏览器把响应拦截，JS 拿不到响应内容

非简单请求（预检）：先发 OPTIONS 请求问服务器
服务器不允许 → 浏览器拒绝发真正的请求

所以跨域是浏览器的行为，服务器看到的请求都到了
这也是为什么服务器之间调用没有跨域问题（没有浏览器同源策略）

# 预检请求（Preflight）什么情况触发

满足以下所有条件 = 简单请求（不触发预检）：

方法只能是：GET / POST / HEAD

请求头只能是：
Accept
Accept-Language
Content-Language
Content-Type（且值只能是以下三种）：
text/plain
multipart/form-data
application/x-www-form-urlencoded

★ 常见的 application/json 不在其中！
所以 POST + JSON body → 触发预检！

非简单请求

以下任意一条 = 非简单请求 → 触发预检：

① 方法是 PUT / DELETE / PATCH / OPTIONS
② Content-Type 是 application/json
③ 请求头包含自定义头：
Authorization（Token 认证）
X-Request-Id / X-Custom-Header 等
④ 使用了 ReadableStream
