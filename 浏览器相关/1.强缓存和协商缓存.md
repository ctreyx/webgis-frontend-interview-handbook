# HTTP 缓存机制说一下，强缓存和协商缓存的区别，分别用什么请求头控制？

强缓存：直接不发请求，用本地缓存。协商缓存：发请求问服务器"我的缓存还有效吗"，有效返回 304，无效返回新资源 200。

## 请求流程

```text
浏览器发请求
↓
本地有缓存？
├── 没有 → 直接请求服务器 → 200 返回资源
└── 有缓存 → 检查强缓存
↓
Cache-Control / Expires 还在有效期？
├── 是 → 直接用缓存，不发请求 ← 强缓存命中（200 from cache）
└── 否 → 带上协商缓存头发请求
↓
服务器对比资源有没有变化？
├── 没变 → 304 Not Modified，用本地缓存
└── 变了 → 200 返回新资源，更新缓存
```

## 强缓存 （ Cache-Control ，Expires

不发请求，直接用本地缓存，状态码 200（from memory/disk cache）。

- Cache-Control（HTTP/1.1，优先级更高）

```http
Cache-Control: max-age=86400
```

单位秒，86400 = 1 天。

- Expires（HTTP/1.0，优先级低）

问题：依赖客户端时间，时钟不准就出问题。

## 协商缓存 （Last-Modified ，ETag

发请求，服务器决定用缓存（304）还是返回新资源（200）。

### 方式一：Last-Modified / If-Modified-Since（时间戳对比）

第一次请求：
Response Headers:
Last-Modified: Mon, 20 Oct 2024 10:00:00 GMT ← 服务器告诉你资源最后修改时间

第二次请求（强缓存过期后）：
Request Headers:
If-Modified-Since: Mon, 20 Oct 2024 10:00:00 GMT ← 把时间戳带回去

服务器对比：
资源修改时间 > If-Modified-Since ?
是 → 资源变了 → 200 返回新资源
否 → 没变 → 304 Not Modified，浏览器用本地缓存

1. 时间精度只到秒，1秒内多次修改识别不到
2. 文件内容没变但修改时间变了（比如重新部署）→ 误判为已变更
3. 服务器集群下，不同机器的文件时间可能不一致

### 方式二：ETag / If-None-Match（内容指纹对比，优先级更高）

第一次请求：
Response Headers:
ETag: "abc123def456" ← 服务器根据文件内容生成的哈希值

第二次请求（强缓存过期后）：
Request Headers:
If-None-Match: "abc123def456" ← 把 ETag 带回去

服务器对比：
当前文件的 ETag === If-None-Match ?
相同 → 内容没变 → 304
不同 → 内容变了 → 200 返回新资源 + 新 ETag

## 不同资源的缓存策略

| 资源类型                                      | 推荐策略                                        | 说明                                                                                             |
| --------------------------------------------- | ----------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| HTML 文件                                     | `Cache-Control: no-cache`                       | 每次都协商，保证拿到最新入口。不能强缓存，否则 JS/CSS 更新了但 HTML 还是老的，用户看不到新版本。 |
| JS / CSS（带 hash 文件名，如 main.abc123.js） | `Cache-Control: max-age=31536000, immutable`    | 缓存一年，内容变了文件名就变（hash 变了）。immutable 告诉浏览器内容永不变，不需要协商。          |
| 图片 / 字体等静态资源                         | `Cache-Control: max-age=604800` + `ETag: "xxx"` | 有一定缓存时间，过期再协商。                                                                     |
| API 接口                                      | `Cache-Control: no-store`                       | 接口数据实时性要求高，完全不缓存。或者交给应用层自己控制（SWR / React Query）。                  |
