
# CommonJS 和 ESM 的区别

> **一句话总结**：CommonJS 是社区定义的**运行时 API**（`require`/`module.exports`），ESM 是官方定义的**静态语法**（`import`/`export`），静态语法是 Tree Shaking 的前提。

---

## 一、定义与本质

| 维度 | CommonJS | ESM |
|---|---|---|
| **来源** | 社区规范（Node.js 采纳） | ECMAScript 官方标准 |
| **性质** | 新增的 **API** | 新增的**语法** |
| **加载时机** | 运行时加载 | 编译时静态分析 + 运行时 |
| **能否放 if 里** | ✅ 可以 | ❌ 不行（`import` 必须在顶层） |
| **Tree Shaking** | ❌ 难 | ✅ 支持 |

> ESM 是静态语法，打包工具在**运行之前**就能做依赖分析，所以 Tree Shaking 必须是 ESM 格式。

---

## 二、语法对比

```js
// ============ CommonJS ============
const fs = require('fs')
const { readFile } = require('fs')
module.exports = { foo }
exports.bar = bar

// ============ ESM ============
import fs from 'fs'
import { readFile } from 'fs'
export const foo = 'foo'
export default bar
```

---

## 三、加载时机（最重要的区别）

```js
// CommonJS —— 运行时加载，可以动态使用
if (condition) {
  const module = require('./a')   // ✅ 可以写在 if 里
}

// ESM —— 编译时静态分析，必须在顶层
if (condition) {
  import module from './a'        // ❌ 语法错误
}
// 如果需要动态导入，用 import()
const module = await import('./a') // ✅ 返回 Promise
```

> **面试话术**："CommonJS 的 `require()` 本质上就是一个函数调用，代码跑到那一行才会执行，所以可以写在任何位置。而 ESM 的 `import` 是声明式的，在代码执行之前就已经被引擎静态分析完毕了，所以必须写在模块顶层。"

---

## 四、值的拷贝 vs 引用（活绑定）

```js
// ============ CommonJS —— 值的拷贝 ============
// counter.js
let count = 0
module.exports = { count, increment: () => count++ }

// main.js
const { count, increment } = require('./counter')
increment()
console.log(count)  // 0 ❗ 还是旧值，拿到的是拷贝

// ============ ESM —— 值的引用（实时绑定） ============
// counter.mjs
export let count = 0
export function increment() { count++ }

// main.mjs
import { count, increment } from './counter.mjs'
increment()
console.log(count)  // 1 ✅ 实时反映最新值
```

> **面试话术**："CommonJS 导出的是值的浅拷贝，模块内部的变化不会反映到外部。而 ESM 导出的是值的**只读活绑定（live binding）**，模块内部修改后，外部引用会同步更新。"

---

## 五、this 指向

```js
// CommonJS
console.log(this === module.exports)  // true ← this 指向当前模块

// ESM
console.log(this)                     // undefined ← ESM 中顶层 this 是 undefined
```

---

## 六、面试加分点：为什么 ESM 能 Tree Shaking？

正是因为 ESM 是**编译时静态分析**的，打包工具（如 Webpack / Rollup）在构建阶段就能确定哪些 export 被 import 了、哪些没有，从而把没用到的代码删掉。

而 CommonJS 的 `require()` 是**运行时动态执行**的，打包工具无法在静态分析阶段确定哪些代码会被用到，所以很难做 Tree Shaking。
