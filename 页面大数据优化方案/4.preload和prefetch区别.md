# preload和prefetch核心区别

一句话总结：**preload是"现在就加载，马上要用"；prefetch是"空闲时加载，之后可能用"。**


preload 告诉浏览器：**这个资源本页当前就需要，优先级很高，尽快下载。**
prefetch 告诉浏览器：**这个资源下一个页面可能需要，等当前页完全加载完、网络空闲时再下载。**


---

# preload（预加载）

## 概念

```html
<link rel="preload" href="critical-font.woff2" as="font" crossorigin>
<link rel="preload" href="hero-image.webp" as="image">
<link rel="preload" href="chunk-critical.js" as="script">
```

preload 告诉浏览器：**这个资源本页当前就需要，优先级很高，尽快下载。**

## 特点

- **优先级高**：和当前页资源同等对待，浏览器立即发起请求
- **当前导航**：资源被当前页面使用，不是给下一个页面用的
- **不阻塞渲染但影响加载**：虽然不阻塞 document 的 onload 事件，但会抢占带宽
- **必须消费**：如果 preload 的资源 3 秒内未被使用，Chrome 会在控制台打印警告
- **as 属性必填**：告诉浏览器资源类型，决定优先级和 CORS 策略

## 常见使用场景

1. **关键字体文件**：字体晚了会导致文字闪烁（FOIT/FOUT），preload 让字体尽早到位
2. **首屏大图 / Hero 图**：首屏背景图如果是 CSS 中 background-image 引入，浏览器要等 CSSOM 构建完才发现，preload 可提前加载
3. **关键 CSS / JS 分包**：Vite 打包后的异步 chunk，如果知道某个 chunk 首屏必用，可以 preload
4. **动态导入的 JSON 数据**：比如地图配置文件、GeoJSON 数据，首屏就需要的可以 preload

## as 属性取值与优先级

| as 值 | 资源类型 | 默认优先级 |
|-------|---------|-----------|
| `style` | CSS | Highest |
| `font` | 字体 | High |
| `script` | JS | High |
| `image` | 图片 | Low（视口内升为 High） |
| `fetch` | XHR/fetch | High |

> 注意：字体即使 as="font" 优先级 High，如果没有 crossorigin 属性，浏览器会忽略 preload 重新请求，造成二次下载。

# prefetch（预取）

## 概念

```html
<link rel="prefetch" href="next-page.js" as="script">
<link rel="prefetch" href="next-page.css" as="style">
```

prefetch 告诉浏览器：**这个资源下一个页面可能需要，等当前页完全加载完、网络空闲时再下载。**

## 特点

- **优先级最低**：等所有当前页资源加载完，网络空闲时才发起
- **未来导航**：资源是为**下一个页面/路由**准备的，不是当前页
- **不影响当前页性能**：不抢带宽，不阻塞渲染
- **可能被取消**：如果用户在当前页停留时间很短就跳走了，prefetch 的资源可能还没下载完就被取消
- **缓存命中**：prefetch 下载完存入 HTTP 缓存，跳转时直接从缓存取，实现秒开

## 常见使用场景

1. **路由预取**：SPA 中，鼠标 hover 到菜单时 prefetch 对应页面的 JS bundle
2. **下一页预取**：分页列表，prefetch 第 2 页数据
3. **低优先级资源**：首页不需要，但子页面肯定用的字体/图标库
4. **懒加载的资源提前预热**：比如地图非首屏图层，空闲时先拉到缓存

# preload vs prefetch 对比表

| 维度 | preload | prefetch |
|------|---------|----------|
| **使用时机** | 当前页面马上就要用 | 下一个导航/未来的页面才用 |
| **优先级** | 高（和当前页资源同级） | 最低（空闲时才加载） |
| **下载时机** | 立即下载 | 当前页加载完成后，网络空闲时 |
| **是否抢占带宽** | 会，可能延迟其他资源 | 不会，完全避开关键路径 |
| **缓存行为** | 下载后存入 memory/disk cache | 下载后存入 HTTP 缓存 |
| **未使用警告** | 3秒未被使用，Console 警告 | 无警告（本来就是可选的） |
| **典型用途** | 字体、首屏图片、关键 chunk | 下一页 JS、预判路由、预热缓存 |

# subresource、preconnect、dns-prefetch、prerender

完整资源提示体系：

```html
<!-- DNS 预解析：仅解析域名，不下载资源 -->
<link rel="dns-prefetch" href="https://api.example.com">

<!-- 预连接：DNS + TCP + TLS 全做完，就差发请求 -->
<link rel="preconnect" href="https://api.example.com">

<!-- 预加载：立即下载，当前页用 -->
<link rel="preload" href="critical.js" as="script">

<!-- 预取：空闲时下载，未来用 -->
<link rel="prefetch" href="next-page.js" as="script">

<!-- 预渲染：在后台隐藏标签页完整渲染整个页面 -->
<link rel="prerender" href="next-page.html">
```

按"深度"排序：`dns-prefetch` < `preconnect` < `prefetch` < `preload` < `prerender`

> prerender 最重，Chrome 已废弃改为 NoState Prefetch，不再执行 JS 只预取资源。

# 在 WebGIS / 大数据页面中的实践

## 场景1：地图首屏关键资源

```html
<!-- 首屏必用的 Cesium JS，preload 确保不排队 -->
<link rel="preload" href="/cesium/Cesium.js" as="script">

<!-- 首屏瓦片图层的基础样式，preload 避免白底闪烁 -->
<link rel="preload" href="/styles/basemap.json" as="fetch" crossorigin>

<!-- 关键字体（标注用），preload 防止标注文字闪烁 -->
<link rel="preload" href="/fonts/noto-sans-sc.woff2" as="font" crossorigin>
```

## 场景2：地图非首屏图层 prefetch

```html
<!-- 用户大概率会点开卫星图层，空闲时拉到缓存 -->
<link rel="prefetch" href="/layers/satellite/0.mvt" as="fetch" crossorigin>

<!-- 切换到的城市（如北京→上海），预取新区域的 GeoJSON -->
<link rel="prefetch" href="/data/shanghai-districts.geojson" as="fetch" crossorigin>
```

## 场景3：SPA 路由预取 + 地图结合

```js
// React Router / Vue Router 中，hover 菜单时预取
function onMenuHover(route) {
  const link = document.createElement('link')
  link.rel = 'prefetch'
  link.as = 'script'
  link.href = `/chunks/${route}.js`
  document.head.appendChild(link)
}
```

## 场景4：10万气象站点数据的分层策略

```html
<!-- 首屏可视站点（5000个点） → preload 立即拉 -->
<link rel="preload" href="/data/stations-viewport.json" as="fetch" crossorigin>

<!-- 缩放后会显示的详细数据 → prefetch 空闲拉 -->
<link rel="prefetch" href="/data/stations-detail.json" as="fetch" crossorigin>

<!-- 非首屏图层（风场粒子、等值面）→ prefetch 空闲拉 -->
<link rel="prefetch" href="/layers/wind-field.js" as="script">
```

# 常见坑 & 注意事项

## 1. preload 字体漏写 crossorigin

```html
<!-- ❌ 错误：缺少 crossorigin，字体会被下载两次 -->
<link rel="preload" href="/fonts/my.woff2" as="font">

<!-- ✅ 正确：字体请求必须带 crossorigin -->
<link rel="preload" href="/fonts/my.woff2" as="font" crossorigin>
```

原因：`@font-face` 发起的是 CORS 请求，preload 必须匹配相同的 CORS 模式，否则缓存不命中。

## 2. preload 和实际资源 URL 不一致

```html
<!-- ❌ preload 的是 /app.js，实际 <script> 引入的是 /app.js?v=123 -->
<link rel="preload" href="/app.js" as="script">
<script src="/app.js?v=123"></script>
```

URL 必须完全一致（包括 query string），否则命中不了缓存，又下载一次。

## 3. 滥用 preload 导致关键资源排队

preload 优先级太高，如果给不重要的资源加了 preload，它们会和关键资源抢带宽，反而拖慢首屏。**只 preload 3~5 个最关键资源。**

## 4. prefetch 在慢网下意义不大

prefetch 依赖"空闲时间"，如果页面本身资源都下不完（比如 2G 网络），就永远不会进入空闲期，prefetch 永远不会触发。

## 5. 不要给当前页用的资源加 prefetch

prefetch 优先级最低，如果当前页需要这个资源但用了 prefetch 而不是 preload，会等到所有资源加载完才下载，体验极差。

## 6. 动态 preload 要小心重复下载

```js
// ❌ 如果 Vite 已经自动注入了 modulepreload，
//    再手动加 preload 可能造成重复
const link = document.createElement('link')
link.rel = 'preload'
link.href = chunkUrl

// ✅ 先检查是否已存在
if (!document.querySelector(`link[href="${chunkUrl}"]`)) {
  document.head.appendChild(link)
}
```

# Vite 中的 modulepreload

Vite 生产构建会自动为动态 import 的模块注入 `<link rel="modulepreload">`：

```html
<!-- Vite 自动生成 -->
<link rel="modulepreload" href="/assets/chunk-abc123.js">
```

`modulepreload` 是 preload 的"ES Module 版"，专门用于预加载 ES 模块，浏览器会同时解析模块依赖图。但它优先级也高，过多的 modulepreload 也会抢带宽，Vite 的 `build.modulePreload.polyfill` 可以控制行为。

# 记忆口诀

```
preload → 现在就下，马上要用（高优，本页）
prefetch → 闲着再下，以后再说（低优，下页）
```

- 本页关键资源 → **preload**
- 下页/未来资源 → **prefetch**
- API 域名 → **preconnect**
- 静态资源域名 → **dns-prefetch**
