# 面试怎么说 

"Web Worker 通过 postMessage 通信，默认是结构化克隆，大数据会有性能问题。我们天气项目的格点数据量很大，如果要用 Worker 优化，我会把数据转成 ArrayBuffer，用 Transferable 方式零拷贝传递，避免内存翻倍和拷贝耗时。"




# postMessage 传大数据的问题

┌──────────────────────────────────────────────────────┐
│  默认 postMessage 传递数据是 结构化克隆                │
│                                                       │
│  也就是深拷贝！                                       │
│                                                       │
│  主线程的数据  ──深拷贝──→  Worker 线程的数据           │
│                                                       │
│  问题：                                               │
│  100MB 的气象格点数据                                  │cc
│  深拷贝一次 → 内存瞬间翻倍变成 200MB                   │
│  而且拷贝过程本身就很耗时                               │
│  可能光拷贝就要几百毫秒                                │
│  还没开始计算，主线程就已经卡了                         │
└──────────────────────────────────────────────────────┘


# Transferable Objects（转移所有权）

// 不是拷贝，而是把内存所有权转移给 Worker
// 零拷贝，速度极快

// 主线程
const buffer = new ArrayBuffer(1024 * 1024 * 100)  // 100MB

// 第二个参数是 transfer 列表
worker.postMessage(buffer, [buffer])

// 转移后主线程的 buffer 变成空的！
console.log(buffer.byteLength)  // 0  ← 主线程不能再用了

// Worker 里
self.onmessage = (e) => {
  const buffer = e.data    // Worker 拿到了完整的 buffer
  // 处理完再转移回去
  self.postMessage(buffer, [buffer])
}


┌──────────────────────────────────────────────────────┐
│  结构化克隆 vs Transferable                           │
│                                                       │
│  结构化克隆：                                          │
│  主线程 100MB ──拷贝──→ Worker 100MB                  │
│  内存：200MB                                          │
│  耗时：几百毫秒                                       │
│                                                       │
│  Transferable：                                       │
│  主线程 0MB ──转移──→ Worker 100MB                    │
│  内存：100MB（没有增加）                               │
│  耗时：接近 0ms                                       │
└──────────────────────────────────────────────────────┘

# Web Worker 里能使用哪些 API？

## 一句话总结

> Worker 里「有计算、有网络、有存储，没有 DOM」。凡是和 DOM、window 对象、阻塞式 UI 相关的一律不能用，其余 Web API 基本都能用。

---

## 一、能用的 API

### 1. 通信相关

| API | 说明 |
|---|---|
| `self.postMessage()` | 向主线程发消息 |
| `self.onmessage` | 接收主线程消息 |
| `MessageChannel` | 双通道通信，可把端口转给多个 Worker |
| `BroadcastChannel` | 同源多上下文广播（Worker ↔ Worker / 页面） |

### 2. 定时器

| API | 说明 |
|---|---|
| `setTimeout` / `setInterval` | 普通定时器 |
| `clearTimeout` / `clearInterval` | 清除定时器 |

> 注意：Worker 里没有 `requestAnimationFrame`（没有渲染循环），定时器精度也和主线程一样受 event loop 影响。

### 3. 网络请求

| API | 说明 |
|---|---|
| `fetch()` | 最常用的网络请求 |
| `XMLHttpRequest` | 老式请求，也支持 |
| `WebSocket` | 长连接 |
| `EventSource` | SSE 服务端推送 |

### 4. 数据存储

| API | 说明 |
|---|---|
| `IndexedDB` | 异步数据库，大量结构化数据 |
| `Cache API`（`caches`） | 配合 Service Worker 缓存资源 |

> ⚠️ `localStorage` / `sessionStorage` 在 Worker 里**不可用**（它们挂在 window 上）。要持久化数据请用 IndexedDB。

### 5. 二进制 / 编码 / 文件

| API | 说明 |
|---|---|
| `ArrayBuffer` / `TypedArray` / `DataView` | 二进制数据（配合 Transferable 零拷贝） |
| `TextEncoder` / `TextDecoder` | 字符串 ↔ 字节流转换 |
| `Blob` / `File` | 文件对象 |
| `FileReader` / `FileReaderSync` | 读文件（Sync 版仅 Worker 可用） |
| `createImageBitmap` | 图片解码成位图（常用在图像处理） |

### 6. 加密

| API | 说明 |
|---|---|
| `crypto.subtle` | Web Crypto API，异步加解密、哈希、签名 |
| `crypto.getRandomValues` | 生成随机数 |

> 大量数据做哈希/加密时放 Worker，避免卡主线程。

### 7. 性能与导航

| API | 说明 |
|---|---|
| `performance.now()` | 高精度时间 |
| `performance.mark/measure` | 性能打点 |
| `navigator`（部分） | 如 `navigator.hardwareConcurrency` 看 CPU 核数 |

### 8. 流 API

| API | 说明 |
|---|---|
| `ReadableStream` / `WritableStream` / `TransformStream` | 流式处理大数据，边收边算 |

### 9. Worker 进阶

| API | 说明 |
|---|---|
| `importScripts()` | 经典 Worker 里同步导入脚本 |
| `new Worker()` | Worker 里还能再创建子 Worker |
| `OffscreenCanvas` | 把 Canvas 渲染搬到 Worker，配合 `transferControlToOffscreen` |

---

## 二、不能用的 API（面试高频考点）

| API | 原因 |
|---|---|
| `document` / DOM 元素 | Worker 没有渲染上下文，无法操作页面 |
| `window` | Worker 的全局对象是 `self`，不是 window |
| `localStorage` / `sessionStorage` | 挂在 window 上，Worker 访问不到 |
| `alert` / `confirm` / `prompt` | 阻塞式 UI，没有界面 |
| `requestAnimationFrame` | 没有渲染循环 |

---

## 三、面试怎么答

> "Worker 的全局对象是 `self`，没有 `window` 和 `document`，所以操作 DOM 的 API 和 `localStorage` 都不能用。但它能用大部分 Web API：`fetch`、`WebSocket`、`IndexedDB`、`Web Crypto`、`TextEncoder`、定时器这些都有。
>
> 我们处理大数据时主要用两个：一是 `fetch` 拉数据在 Worker 里做解析和计算，二是 `ArrayBuffer` + `Transferable` 做零拷贝通信。像天气项目的格点数据解析、雷达图数据解压，都是放 Worker 里算，算完用 Transferable 把结果转回主线程。"

---

## 四、代码示例：Worker 里综合使用 API

```js
// worker.js
self.onmessage = async (e) => {
  // ① 接收 Transferable 数据
  const rawBuffer = e.data

  // ② 用 TextDecoder 解码
  const decoder = new TextDecoder('utf-8')
  const text = decoder.decode(rawBuffer)

  // ③ 在 Worker 里做 CPU 密集计算
  const result = heavyCompute(text)

  // ④ 用 TextEncoder 编码回二进制
  const encoder = new TextEncoder()
  const outBuffer = encoder.encode(result).buffer

  // ⑤ 用 fetch 请求远程数据（Worker 里可以）
  // const resp = await fetch('/api/grid-data')
  // const data = await resp.arrayBuffer()

  // ⑥ 用 crypto 做哈希
  // const digest = await crypto.subtle.digest('SHA-256', outBuffer)

  // ⑦ Transferable 零拷贝传回主线程
  self.postMessage(outBuffer, [outBuffer])
}

function heavyCompute(text) {
  // 模拟 CPU 密集计算
  let sum = 0
  for (let i = 0; i < 1000000; i++) {
    sum += i
  }
  return text + sum
}
```
