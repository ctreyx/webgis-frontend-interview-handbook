# 面试怎么说 

"Web Worker 通过 postMessage 通信，默认是结构化克隆，大数据会有性能问题。我们天气项目的格点数据量很大，如果要用 Worker 优化，我会把数据转成 ArrayBuffer，用 Transferable 方式零拷贝传递，避免内存翻倍和拷贝耗时。"




# postMessage 传大数据的问题

┌──────────────────────────────────────────────────────┐
│  默认 postMessage 传递数据是 结构化克隆                │
│                                                       │
│  也就是深拷贝！                                       │
│                                                       │
│  主线程的数据  ──深拷贝──→  Worker 线程的数据           │
│                                                       │
│  问题：                                               │
│  100MB 的气象格点数据                                  │cc
│  深拷贝一次 → 内存瞬间翻倍变成 200MB                   │
│  而且拷贝过程本身就很耗时                               │
│  可能光拷贝就要几百毫秒                                │
│  还没开始计算，主线程就已经卡了                         │
└──────────────────────────────────────────────────────┘


# Transferable Objects（转移所有权）

// 不是拷贝，而是把内存所有权转移给 Worker
// 零拷贝，速度极快

// 主线程
const buffer = new ArrayBuffer(1024 * 1024 * 100)  // 100MB

// 第二个参数是 transfer 列表
worker.postMessage(buffer, [buffer])

// 转移后主线程的 buffer 变成空的！
console.log(buffer.byteLength)  // 0  ← 主线程不能再用了

// Worker 里
self.onmessage = (e) => {
  const buffer = e.data    // Worker 拿到了完整的 buffer
  // 处理完再转移回去
  self.postMessage(buffer, [buffer])
}


┌──────────────────────────────────────────────────────┐
│  结构化克隆 vs Transferable                           │
│                                                       │
│  结构化克隆：                                          │
│  主线程 100MB ──拷贝──→ Worker 100MB                  │
│  内存：200MB                                          │
│  耗时：几百毫秒                                       │
│                                                       │
│  Transferable：                                       │
│  主线程 0MB ──转移──→ Worker 100MB                    │
│  内存：100MB（没有增加）                               │
│  耗时：接近 0ms                                       │
└──────────────────────────────────────────────────────┘
