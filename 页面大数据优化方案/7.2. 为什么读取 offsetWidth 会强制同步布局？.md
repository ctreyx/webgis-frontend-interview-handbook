# 为什么读取 offsetWidth 会强制同步布局？

---

## 一、浏览器的"懒计算"策略

浏览器为了性能，不会每次改 DOM/CSS 就立刻重新 Layout，而是**批量收集变更**，统一在合适时机计算：

```
JS 执行期间：
  改了 div 宽度  →  先标记"需要重新 Layout"，不立即计算
  改了颜色       →  继续标记
  ...

JS 执行完毕  →  统一 Layout → Paint → Composite
```

---

## 二、读取 `offsetWidth` 时发生了什么？

浏览器**必须给你此刻准确的值**。

如果有未计算的样式变更堆积着，浏览器就必须**立即同步执行 Layout**，才能给你正确答案。

```js
// 这段代码触发强制同步布局
div.style.width = '200px'  // 标记：需要重新 Layout
div.offsetWidth            // 浏览器：你要读宽度？
                           // 我必须现在立刻 Layout，不能等了！
                           // → 强制同步 Layout
```

---

## 三、为什么这很危险？

```js
// ❌ 错误写法 —— 读写交替
for (let i = 0; i < 100; i++) {
  div.style.width = i + 'px'    // 写，标记需要 Layout
  console.log(div.offsetWidth)  // 读，强制立即 Layout
  // 每次循环都触发一次 Layout → 100 次强制 Layout
}
```

```js
// ✅ 正确写法 —— 读写分离
const width = div.offsetWidth  // 先统一读
for (let i = 0; i < 100; i++) {
  div.style.width = width + i + 'px'  // 再统一写
}
// 只触发一次 Layout
```
