# 坑一：鼠标事件坐标偏移（最常见）

┌──────────────────────────────────────────────────────┐
│  问题：                                               │
│                                                       │
│  scale 缩放后，DOM 的视觉位置变了                      │
│  但浏览器的事件坐标系没变                               │
│                                                       │
│  比如 scale(0.5)                                     │
│  一个按钮视觉上在 (100, 100)                          │
│  但实际 DOM 的位置还是 (200, 200)                     │
│  点击视觉位置 (100,100) 点不到按钮！                   │
│                                                       │
│  但是！如果你是整个 body 缩放                          │
│  浏览器会自动处理事件映射                               │
│  所以普通的点击按钮是没问题的 ✅                        │
│                                                       │
│  真正出问题的是这些场景：                               │
│  - Cesium/OpenLayers 的地图点击拾取坐标                │
│  - Canvas 上的鼠标事件                                │
│  - 第三方弹窗库的定位（比如右键菜单）                   │
│  - 拖拽排序的坐标计算                                  │

// 解决方案：
// 地图容器单独处理坐标换算
const viewer = new Cesium.Viewer('cesium-container')
const handler = new Cesium.ScreenSpaceEventHandler(viewer.canvas)

handler.setInputAction((event) => {
  const scale = getCurrentScale()
  
  // 原始坐标除以 scale 得到真实坐标
  const position = new Cesium.Cartesian2(
    event.position.x / scale,
    event.position.y / scale
  )
  
  const picked = viewer.scene.pick(position)
}, Cesium.ScreenSpaceEventType.LEFT_CLICK)


# 坑二：字体模糊

┌──────────────────────────────────────────────────────┐
│  问题：                                               │
│                                                       │
│  scale 是位图缩放，不是矢量缩放                        │
│  放大的时候（scale > 1）字体会变模糊                    │
│  特别是小字号的文字，边缘会有锯齿                       │
│                                                       │
│  比如 4K 屏 3840×2160                                 │
│  scale = 3840/1920 = 2                               │
│  所有文字放大 2 倍，明显模糊                           │
└──────────────────────────────────────────────────────┘

// 解决方案：
body {
  transform: scale(2);
  
  /* 开启抗锯齿 */
  -webkit-font-smoothing: antialiased;
  -moz-osx-font-smoothing: grayscale;
  
  /* 告诉浏览器用 3D 渲染优化 */
  transform: scale(2) translateZ(0);
  
  /* 如果还模糊，可以用 zoom 替代 scale */
  /* zoom 是真实缩放，不是位图缩放 */
}

# 完整的 Scale 方案（生产可用版本）


// useScale.js
export const useScale = () => {
  const designWidth = 1920
  const designHeight = 1080
  
  const setScale = () => {
    const scaleX = window.innerWidth / designWidth
    const scaleY = window.innerHeight / designHeight
    const scale = Math.min(scaleX, scaleY)
    
    // 存到 CSS 变量，方便其他地方用
    document.documentElement.style.setProperty('--scale', scale)
    
    const container = document.getElementById('app')
    container.style.transform = `scale(${scale})`
    container.style.transformOrigin = 'top left'
    container.style.width = `${designWidth}px`
    container.style.height = `${designHeight}px`
    
    // 居中显示（如果比例不一致会有留白）
    const marginLeft = (window.innerWidth - designWidth * scale) / 2
    const marginTop = (window.innerHeight - designHeight * scale) / 2
    container.style.marginLeft = `${marginLeft}px`
    container.style.marginTop = `${marginTop}px`
  }
  
  // 防抖，避免 resize 频繁触发
  let timer = null
  const onResize = () => {
    clearTimeout(timer)
    timer = setTimeout(setScale, 100)
  }
  
  onMounted(() => {
    setScale()
    window.addEventListener('resize', onResize)
  })
  
  onUnmounted(() => {
    window.removeEventListener('resize', onResize)
    clearTimeout(timer)
  })
  
  // 暴露 scale 值给其他组件用（比如地图坐标换算）
  const getScale = () => {
    return parseFloat(
      document.documentElement.style.getPropertyValue('--scale')
    )
  }
  
  return { getScale }
}

## 面试表述（完整版，3 分钟讲完）

> **【背景】** 我们的大屏项目面向多种交付场景——有标准的 1920×1080 会议大屏，也有 4K/8K 展示屏，甚至还有**军区双面屏**这种特殊形态：同一台主机驱动两块 55 寸屏幕，分辨率相当于 3840×1080（或 1920×2160），比例完全不同于常规 16:9。
>
> **【方案演进】** 最初用的是 rem + 媒体查询断点方案，但断点式适配在面对 1366×768、1920×1080、2560×1440、3840×2160 等十几种分辨率时精度不够，维护成本高。后来改成了 **scale 整体缩放方案**：以 1920×1080 为设计基准，监听 resize 动态计算 Math.min(scaleX, scaleY)，用 transform: scale() + transformOrigin: top left + 居中 margin 实现等比缩放。
>
> **【双面屏适配】** 军区项目的双面屏是一个特殊挑战——它不是常规的扩展屏，而是**一张逻辑 canvas 横跨两块物理屏幕**，分辨率变成 3840×1080（宽高比 32:9）。常规的 Math.min(scaleX, scaleY) 策略会导致画面缩得极小（因为 Y 轴只需要 scaleY=1，但 X 轴 scaleX=0.5，取 min 两个方向都缩 0.5→画面只有屏幕一半高）。我做的改造是：
> - 引入 **fitMode 配置项**：contain（默认，留白优先）/ cover（铺满优先）/ fill（拉伸填满）
> - 双面屏场景使用 fitMode: cover，取 Math.max 保证画面撑满，超出部分用 overflow: hidden 裁剪
> - 对于双面屏的「左右屏显示不同内容」，通过 CSS 变量 --scale 传入每个子区域，各自独立校准坐标
>
> **【踩坑与解决】**
> 1. **Cesium 地图坐标偏移**：scale 后浏览器事件坐标和真实 DOM 坐标不一致，Cesium 的 ScreenSpaceEventHandler 拿到的 event.position 需要除以 scale 才能正确拾取。封装了 useMapCoordinate hook，对所有地图交互统一做坐标换算。
> 2. **字体模糊**：scale 是位图缩放，放大超过 1.5 倍后明显模糊。通过 translateZ(0) 强制 GPU 渲染 + font-smoothing: antialiased + 对 4K 以上自动切换 zoom 替代 transform 三管齐下解决。
> 3. **Echarts / 第三方 Canvas 库**：Canvas 内部坐标体系和 scale 不兼容，tooltip 位置漂移。方案是给图表容器反向 scale：transform: scale(1/var(--scale))，让图表在「真实像素」下渲染再缩回去。
>
> **【工程化】** 最终封装成 useScale composable + CSS 变量体系，外部组件通过 inject('scale') 获取当前 scale 值。配合 ResizeObserver（代替 window.resize 监听容器变化）和 requestAnimationFrame 防抖，避免频繁重排。整个方案经过 10+ 种分辨率实测，适配成功率 100%。

## 技术深度递进（面试官可能会追问的方向）

1. **Q: scale 和 zoom 有什么区别？** → scale 是 CSS transform，不影响布局流，zoom 是 IE 时代属性，会触发 reflow。4K 以上优先用 zoom。
2. **Q: 为什么不用 vw/vh 方案？** → vw/vh 只能做线性缩放，无法处理宽高比不一致时的留白/裁剪策略。
3. **Q: 双面屏两个屏幕显示不同内容怎么实现？** → 通过 flex 布局将页面分成左右两个 panel，各自独立绑定 scale，通过 CSS 变量隔离。
4. **Q: ResizeObserver 和 window.resize 有什么区别？** → ResizeObserver 可以监听任意元素尺寸变化，不会因为 iframe、sidebar 展开等非窗口变化漏触发。
