
# 性能降级方案：自动检测性能并切换渲染策略

> **核心思想**：预检测定基准，运行时做兜底，让渲染质量和设备性能自动匹配。

---

## 第一层：性能检测（进页面时）

```js
class PerformanceDetector {
  async detect() {
    // 1. 检测 WebGL 能力
    const canvas = document.createElement('canvas')
    const gl = canvas.getContext('webgl2') || canvas.getContext('webgl')
    if (!gl) return 'low' // 不支持 WebGL，直接降级

    // 2. 检测 GPU 信息
    const ext = gl.getExtension('WEBGL_debug_renderer_info')
    const renderer = gl.getParameter(ext.UNMASKED_RENDERER_WEBGL)
    // 集成显卡关键词检测
    const isLowGPU = /intel|mali|adreno 3|adreno 4/i.test(renderer)

    // 3. 跑一个基准测试，测试实际帧率
    const fps = await this.measureFPS()
    
    if (fps < 30 || isLowGPU) return 'low'
    if (fps < 50) return 'medium'
    return 'high'
  }

  measureFPS() {
    return new Promise(resolve => {
      let frames = 0
      const start = performance.now()
      const count = () => {
        frames++
        if (performance.now() - start < 1000) {
          requestAnimationFrame(count)
        } else {
          resolve(frames)
        }
      }
      requestAnimationFrame(count)
    })
  }
}
```

**检测三要素：**
1. WebGL 上下文是否存在（`webgl2` → `webgl`）
2. GPU 型号（`WEBGL_debug_renderer_info` 拿 renderer，匹配集成显卡关键词）
3. 实际帧率基准测试（rAF 跑 1 秒数帧数）

## 第二层：降级策略分级

```js
const RENDER_STRATEGY = {
  high: {
    // 全量渲染，WebGL 纹理方案
    gridCount: 'full',         // 全量格点
    renderMode: 'webgl',       // WebGL 渲染
    interpolation: true,       // 开启插值平滑
    workerCount: 4,            // 多 Worker 并行
  },
  medium: {
    gridCount: 'sample_50',    // 抽稀 50%
    renderMode: 'canvas2d',    // 降级 Canvas 2D
    interpolation: true,
    workerCount: 2,
  },
  low: {
    gridCount: 'sample_20',    // 只渲染 20% 格点
    renderMode: 'canvas2d',    // Canvas 2D
    interpolation: false,      // 关闭插值，直接填色
    workerCount: 1,
  }
}
```

**三档策略对照：**

| 档位 | 格点数 | 渲染模式 | 插值 | Worker |
|---|---|---|---|---|
| high | 全量 | WebGL | ✅ | 4 |
| medium | 抽稀 50% | Canvas 2D | ✅ | 2 |
| low | 抽稀 20% | Canvas 2D | ❌ | 1 |

## 第三层：运行时动态监控

```js
class FPSMonitor {
  constructor(onDrop) {
    this.onDrop = onDrop
    this.frames = []
  }

  start() {
    const tick = () => {
      this.frames.push(performance.now())
      // 只保留最近1秒的帧
      const now = performance.now()
      this.frames = this.frames.filter(t => now - t < 1000)

      // 帧率持续低于 20fps，触发降级
      if (this.frames.length < 20) {
        this.onDrop(this.frames.length)
      }
      requestAnimationFrame(tick)
    }
    requestAnimationFrame(tick)
  }
}

// 使用
const monitor = new FPSMonitor((fps) => {
  if (fps < 20) {
    // 动态减少格点数量
    gridRenderer.setSampleRate(0.3)
    // 关闭插值
    gridRenderer.setInterpolation(false)
  }
})
monitor.start()
```

**运行时降级逻辑：**
- rAF 持续统计最近 1 秒的帧数
- 帧率跌破 20fps 阈值 → 动态调整抽稀比例 + 关闭插值
- 无需刷新页面，运行时自适应降级

> 第二层是根据档位选渲染策略，高配走 WebGL 全量渲染加插值，中配降级到 Canvas 2D 加 50% 抽稀，低配关闭插值只渲染 20% 格点，优先保证页面可用。

> 这套方案的核心思想就是：预检测定基准，运行时做兜底，让渲染质量和设备性能自动匹配。"

## 总结（简历版）

> 针对客户端设备性能差异，设计了三层自适应降级方案：
>
> - **进页面检测**：通过 `WEBGL_debug_renderer_info` 检测 GPU 能力 + rAF 基准测试评估实际帧率，划分高/中/低三个性能档位
> - **按档位切换策略**：WebGL 全量渲染 / Canvas2D 抽稀渲染 / 关闭插值极简渲染
> - **运行时兜底**：持续监控帧率，跌破阈值时动态调整抽稀比例和渲染精度，结合 Cesium `requestRenderMode` 减少空闲帧渲染
