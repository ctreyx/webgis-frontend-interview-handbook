

# Entity 底层其实还是 Primitive，但它多了 Property 系统每帧求值、Visualizer 翻译、以及无法合批这三层开销。数据量大的时候，直接用 Primitive 跳过这些中间层，配合合批渲染，DrawCall 从几千次降到个位数，性能差距是数量级的。
┌──────────────────────────────────────────────────────┐
│ Entity 的完整架构 │
│ │
│ Entity │
│ ↓ │
│ Property 系统（每帧计算属性值） │
│ ↓ │
│ EntityCollection（管理所有 Entity） │
│ ↓ │
│ Visualizer（把 Entity 翻译成 Primitive） │
│ ↓ │
│ Primitive（真正提交给 WebGL 渲染） │
└──────────────────────────────────────────────────────┘

所以 Entity 最终还是变成 Primitive 来渲染的！
它只是上面多了三层封装。

1. Property 系统（最大的性能杀手） │
   │ │
   │ Entity 的每个属性（position、color、size 等） │
   │ 都不是普通值，而是一个 Property 对象 │
   │ 支持动态变化，比如： │
   │ - 随时间变化的位置（SampledPositionProperty） │
   │ - 条件切换的颜色（CallbackProperty） │
   │ │
   │ 代价：每一帧都要遍历所有 Entity │
   │ 调用每个 Property 的 getValue(time) │
   │ 即使你的值根本没变化，也要算一遍 │
   │ │
   │ 1000 个 Entity × 5 个属性 = 每帧 5000 次 getValue │
   │ 10000 个就是 50000 次，直接卡死


  2. Visualizer 转换开销                                │
│                                                       │
│  每帧 Visualizer 要做：                                │
│  - 检查哪些 Entity 新增/删除/修改了                     │
│  - 把 Entity 的属性转换成 Primitive 的参数              │
│  - 更新或重建底层的 Primitive                           │
│                                                       │
│  相当于每帧做一次"翻译"工作    


  3. 无法合批                                           │
│                                                       │
│  每个 Entity 被 Visualizer 转成独立的 Primitive        │
│  1000 个 Entity = 1000 个 DrawCall                    │
│                                                       │
│  而 PrimitiveCollection 可以把同类型几何体              │
│  合并成一个 DrawCall 提交给 GPU                         │
│  1000 个点 = 1 个 DrawCall       


┌────────────────┬───────────────────┬───────────────────┐
│                │  Entity            │  Primitive         │
├────────────────┼───────────────────┼───────────────────┤
│ 本质           │ 高层封装           │ 直接对接 WebGL     │
│ 每帧开销       │ Property求值       │ 几乎没有额外开销   │
│                │ + Visualizer转换   │                   │
│ DrawCall       │ 每个 Entity 一个   │ 可合批为一个       │
│ 适合数据量     │ 几百个             │ 上万个             │
│ 开发成本       │ 低，API 简单       │ 高，需要懂图形学   │
│ 动态属性       │ 天然支持           │ 需要手动更新       │
└────────────────┴───────────────────┴───────────────────┘
