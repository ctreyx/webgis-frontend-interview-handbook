# 10万气象站点用 Primitive，但具体用哪个 API

## 一、API 选型

| 展示形式    | 推荐 API                                        | 理由                                  |
| ----------- | ----------------------------------------------- | ------------------------------------- |
| 纯色圆点    | PointPrimitiveCollection                        | 最轻量，一次 DrawCall，GPU 直接绘制点 |
| 图标 / 图片 | BillboardCollection                             | 支持自定义贴图，始终朝向相机          |
| 文字标签    | LabelCollection                                 | 站名展示，底层也是合批渲染            |
| 圆点 + 文字 | PointPrimitiveCollection + LabelCollection 组合 | 各司其职，不混用 Entity               |

## 二、核心原因：合批渲染

```js
// ✅ 正确做法：一个 Collection = 一次 DrawCall
const points = viewer.scene.primitives.add(
  new Cesium.PointPrimitiveCollection(),
);

stationData.forEach((station) => {
  points.add({
    position: Cesium.Cartesian3.fromDegrees(station.lon, station.lat),
    pixelSize: 6,
    color: getColorByValue(station.value), // 根据气象值映射颜色
  });
});
```

底层原理是：Cesium 会把 Collection 内所有点合并成一个顶点缓冲区（VertexBuffer），提交给 GPU 做一次 DrawCall，而不是 10 万次。这是性能关键。

## 三、进一步优化策略

我在实际项目中还会做以下优化：

### 1) 层级聚合（Clustering）

```js
// 缩放级别低时，密集站点聚合成一个气泡
dataSource.clustering.enabled = true;
dataSource.clustering.pixelRange = 30;
dataSource.clustering.minimumClusterSize = 5;
```

视野大时聚合减少绘制，放大后自动展开。

### 2) 视域裁剪（按需加载）

```js
// 监听相机变化，只渲染可视范围内的站点
viewer.camera.changed.addEventListener(() => {
  const rect = viewer.camera.computeViewRectangle();
  // 用 R-tree 空间索引快速筛选视域内的站点
  const visible = spatialIndex.search(rect);
  updateVisiblePoints(visible);
});
```

### 3) 数据分级

- 全国级别：只显示国家站（~2400 个）
- 省级别：加载区域站
- 市级别：加载全量站点

这三层优化配合使用，即使站点到百万级也不会卡顿。
