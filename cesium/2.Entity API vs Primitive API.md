# Entity API vs Primitive API

详细对比
维度 Entity API Primitive API
抽象层级 高层封装 底层接口
核心思想 "我要一个什么东西"（声明式） "我要怎么画"（命令式）
时间动态 ✅ 内建 SampledProperty 自动插值 ❌ 需手动更新
属性绑定 ✅ CallbackProperty 响应式 ❌ 手动管理
拾取信息 ✅ 自动携带 Entity 引用 需手动设置 id
合批能力 ❌ 每个 Entity 独立 draw call ✅ PerInstanceColorAppearance 合批
性能上限 ~1,000-10,000 个对象 10 万+ 对象
自定义着色器 ❌ 不支持 ✅ 完全自定义 Appearance / Material
学习成本 低 高

              Entity	          Primitive

封装层级 高级 DataSource 层 接近底层WebGL
性能 较低 高
动态更新 方便（属性绑定） 需手动更新
适合数量 < 1000 10万+
坐标系 自动处理 需手动转换

```js
// ========== Entity API（简单直观）==========
viewer.entities.add({
  position: Cesium.Cartesian3.fromDegrees(116.4, 39.9),
  point: {
    pixelSize: 10,
    color: Cesium.Color.RED,
  },
  label: {
    text: "北京",
    font: "14px sans-serif",
  },
});

// ========== Primitive API（高性能）==========
const pointCollection = new Cesium.PointPrimitiveCollection();
pointCollection.add({
  position: Cesium.Cartesian3.fromDegrees(116.4, 39.9),
  pixelSize: 10,
  color: Cesium.Color.RED,
});
scene.primitives.add(pointCollection);
```

Entity API 适合：
✅ 少量交互对象（< 几千个）
✅ 需要时间轴动画（轨迹回放、卫星轨道）
✅ 需要 InfoBox / 属性面板展示
✅ 快速原型开发

Primitive API 适合：
✅ 海量数据渲染（数万~百万级点/线/面）
✅ 需要自定义着色器（热力图、流场动画）
✅ 静态或半静态数据可视化
✅ 对帧率有严格要求的生产环境
