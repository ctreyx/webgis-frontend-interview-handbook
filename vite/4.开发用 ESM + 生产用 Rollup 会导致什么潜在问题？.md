# 开发用 ESM + 生产用 Rollup 会导致什么潜在问题？

这是 Vite 架构中最大的已知痛点。

开发阶段，Vite 直接向浏览器提供原生 ES 模块；而构建模式下则使用 Rollup。对这种二元性的误解可能导致开发和生产行为之间出现不一致。

# 问题①：CJS 处理方式不同

11
开发和生产之间存在不一致，原因是 esbuild 和 `@rollup/plugin-commonjs` 在处理 CommonJS 方面存在差异。
JavaScript

// 某些 CJS 包的 default export 处理
// Dev（esbuild 处理）：
import pkg from 'some-cjs-pkg';
pkg.someMethod(); // ✅ 正常

// Prod（Rollup 处理）：
import pkg from 'some-cjs-pkg';
pkg.someMethod(); // ❌ pkg 可能是 { default: { someMethod } }

# 问题②：插件系统不一致

13
更糟糕的是插件系统——esbuild 的插件 API 与 Rollup 的完全不同。为开发阶段编写的插件在生产环境可能无法工作，反之亦然。
