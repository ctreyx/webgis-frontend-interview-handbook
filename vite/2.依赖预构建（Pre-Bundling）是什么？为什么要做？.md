# 二、依赖预构建（Pre-Bundling）是什么？为什么要做？

# 预构建缓存存在 node_modules/.vite/deps

# 依赖没变化时直接用缓存，加速二次启动

# 通过 optimizeDeps.include/exclude 可以手动控制哪些需要预构建

它是什么？
Vite 在首次启动时，用 esbuild 把 node_modules 中的第三方依赖预先打包成单个 ESM 文件，缓存到 node_modules/.vite 目录下。

首次启动流程：

1. 扫描你项目的 import 语句
   → 发现 import { ref } from 'vue'
   → 发现 import lodash from 'lodash-es'

2. esbuild 预构建
   → vue 的内部 100+ 个模块 → 打包成一个 vue.js
   → lodash-es 的 600+ 个模块 → 打包成一个 lodash-es.js

3. 缓存到 node_modules/.vite/deps/
   → 后续启动直接复用缓存，毫秒级

为什么必须做？ 两个核心原因：

# 原因一：CJS → ESM 转换

浏览器只认 ESM，但 npm 上大量包仍是 CommonJS 格式（如 React、moment）：

JavaScript

// ❌ 浏览器无法处理 CommonJS
const React = require('react');
module.exports = Something;

// ✅ 预构建转换为 ESM
export default React;
export { useState, useEffect };

# 原因二：减少请求瀑布（Request Waterfall）

text

没有预构建时：
import { debounce } from 'lodash-es'
↓
浏览器发起 600+ 个 HTTP 请求（lodash-es 有 600+ 个内部模块）
↓
瀑布式请求，页面卡死 💀

预构建后：
import { debounce } from 'lodash-es'
↓
浏览器只发 1 个请求（预构建好的单文件）
↓
毫秒级加载 ✅

# // vite.config.js 中可以手动控制预构建

export default {
optimizeDeps: {
include: ['some-cjs-package'], // 强制预构建
exclude: ['already-esm-package'], // 排除不需要的
}
}
