 
# 生产环境换 Rollup 是因为 Rollup 的 tree-shaking 和代码分割更成熟

esbuild 只用于开发环境转译，不做 tree-shaking
生产环境换 Rollup 是因为 Rollup 的 tree-shaking 和代码分割更成熟

1. esbuild 追求的是速度，Rollup 追求的是产物质量。开发环境要快用 esbuild，生产环境要稳要小用 Rollup，各司其职。

2. 目前 Vite 开发用 esbuild 生产用 Rollup，但未来会用 Rust 写的 Rolldown 统一替代，解决开发和生产构建行为不一致的问题。"



┌──────────────────────────────────────────────────────┐
│  esbuild 缺什么？                                      │
├──────────────────────────────────────────────────────┤
│                                                       │
│  1. 代码分割（Code Splitting）不够灵活                  │
│     Rollup 可以精细控制 chunk 怎么拆分                  │
│     esbuild 的分割策略比较粗糙                          │
│                                                       │
│  2. CSS 处理能力弱                                     │
│     不支持 CSS Modules、PostCSS 等生态                  │
│     生产环境 CSS 优化做不了                              │
│                                                       │
│  3. 插件生态不成熟                                      │
│     Rollup 插件生态非常丰富                              │
│     esbuild 插件 API 比较简单，很多场景覆盖不了           │
│                                                       │
│  4. 不支持 HTML 处理                                    │
│     不能自动注入 script 标签、处理多入口 HTML             │
│                                                       │
│  5. 产物优化不够                                        │
│     Tree Shaking 不如 Rollup 精细                      │
│     Rollup 基于 AST 分析，可以做更深层的死代码消除        │
│                                                       │
└──────────────────────────────────────────────────────┘
