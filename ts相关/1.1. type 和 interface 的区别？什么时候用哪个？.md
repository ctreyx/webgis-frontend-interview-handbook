# type 和 interface 的区别？什么时候用哪个？

# 用 interface 的场景

1. 需要声明合并（扩展第三方类型）
2. 公共 API / 库的对外接口定义 , 比如props等
3. ★ 关键区别：extends 会检查兼容性，type & 不检查

# 你说 declare 方向是对的，但光写同名 interface 是不够的，需要配合 declare module：


// types/axios.d.ts

import 'axios'

// 关键：必须用 declare module 指定扩展哪个模块
declare module 'axios' {
  interface AxiosRequestConfig {
    loading?: boolean    // 扩展你自己的属性
    retry?: number       // 重试次数
  }
}
必须用 declare module 'axios' 告诉 TS                 │
│  我要扩展的是这个模块里的 interface        


# 用 type 的场景

1. 联合类型（interface 做不到） |
2. 工具类型 / 类型体操
3. 元组类型

对外暴露的 API 类型优先 interface（可扩展性好）
内部实现、工具类型、联合状态用 type

差异 1：声明合并 —— interface 独有

```js
// ✅ interface 可以重复声明 → 自动合并
interface Window {
title: string;
}
interface Window {
version: number; // 合并进去了！
}
// 最终 Window = { title: string; version: number }

// ❌ type 重复声明直接报错
type Window = { title: string };
type Window = { version: number }; // Error: 标识符"Window"重复
```

# ★ 实际应用：扩展第三方库的类型定义 ，直接interface描述即可

```js
// 给 axios 的 config 加自定义字段
declare module 'axios' {
interface AxiosRequestConfig {
// 合并进 axios 的原始类型
showLoading?: boolean;
skipErrorHandler?: boolean;
}
}

// 给 window 挂载自定义属性
declare global {
interface Window {
**APP_CONFIG**: AppConfig;
\_hmt: any[]; // 百度统计
}
}
// 用 type 做不到这个！
```

# 差异 2：联合 / 条件 / 映射类型 —— type 独有

```js
// ✅ 联合类型：只有 type 能做
type Status = 'loading' | 'success' | 'error';
type ID = string | number;
type Nullable<T> = T | null;

// ❌ interface 做不到
interface Status = 'loading' | 'success'; // 语法错误！

// ✅ 条件类型：只有 type 能做
type IsString<T> = T extends string ? true : false;
type NonNullable<T> = T extends null | undefined ? never : T;

// ✅ 映射类型：只有 type 能做
type Readonly<T> = {
readonly [K in keyof T]: T[K];
};
type Partial<T> = {
[K in keyof T]?: T[K];
};

// ✅ 工具类型组合：type 的主场
type ApiResponse<T> =
| { status: 'success'; data: T }
| { status: 'error'; message: string }
| { status: 'loading' };
// 这种精确的联合类型，interface 完全无法表达
```

# 差异 3：继承方式不同 interface可以extend type 只能& / ★ 关键区别：extends 会检查兼容性，& 不检查

```js
// interface 用 extends（可多继承）
interface Animal {
name: string;
}
interface Dog extends Animal {
bark(): void;
}
interface GuideDog extends Dog, Serializable { // 多继承
owner: string;
}

// type 用 &（交叉类型）
type Animal = { name: string };
type Dog = Animal & { bark(): void };
type GuideDog = Dog & Serializable & { owner: string };

// ★ 关键区别：extends 会检查兼容性，& 不检查

interface A { x: string }
interface B extends A { x: number } // ❌ Error！string 和 number 不兼容

type A = { x: string }
type B = A & { x: number } // ✅ 不报错，但 x 的类型变成 string & number = never
// 这是个坑！交叉后字段类型变 never，用时才报错
```
