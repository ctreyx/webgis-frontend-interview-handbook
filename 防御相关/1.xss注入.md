# Vue3 默认怎么防御的


┌──────────────────────────────────────────────────────┐
│  Vue3 模板中的 {{ }} 插值表达式                        │
│  会自动做 HTML 转义（Escaping）                        │
│                                                       │
│  比如：                                               │
│  const userInput = '<script>alert(1)</script>'       │
│                                                       │
│  {{ userInput }}                                     │
│  渲染结果：                                           │
│  &lt;script&gt;alert(1)&lt;/script&gt;               │
│                                                       │
│  浏览器把它当成纯文本显示                              │
│  不会当成 HTML 执行                                   │
│  这就是 Vue3 的自动防御 ✅                             │
│                                                       │
│  但 v-html 会跳过转义！                               │
│  直接把字符串当成 HTML 插入 DOM                        │
│  所以 v-html 是 XSS 的入口 ❌                         │
└──────────────────────────────────────────────────────┘



# 正确的防御方案
┌──────────────────────────────────────────────────────┐
│                                                       │
│  方案一：用专业的 XSS 过滤库（推荐）                   │
│                                                       │
│  不要自己写正则！用成熟的库：                           │
│  · DOMPurify（最流行）                                │
│  · xss（Node.js 常用）                               │
│                                                       │
│  import DOMPurify from 'dompurify'                   │
│                                                       │
│  // 过滤后再给 v-html                                 │
│  const clean = DOMPurify.sanitize(dirtyHTML)          │
│                                                       │
│  <div v-html="clean"></div>                          │
│                                                       │
│  DOMPurify 会：                                       │
│  · 移除所有 script 标签                               │
│  · 移除所有事件属性（onerror、onclick 等）             │
│  · 移除 javascript: 伪协议                            │
│  · 处理编码绕过                                       │
│  · 只保留安全的 HTML 标签和属性                        │
│                                                       │
└──────────────────────────────────────────────────────┘

┌──────────────────────────────────────────────────────┐
│                                                       │
│  方案二：能不用 v-html 就不用                          │
│                                                       │
│  大部分场景 {{ }} 插值就够了                           │
│  只有富文本编辑器等场景才需要 v-html                   │
│                                                       │
└──────────────────────────────────────────────────────┘

┌──────────────────────────────────────────────────────┐
│                                                       │
│  方案三：CSP 内容安全策略（后端配合）                   │
│                                                       │
│  服务端返回响应头：                                    │
│  Content-Security-Policy: script-src 'self'          │
│                                                       │
│  告诉浏览器：只允许执行同源的脚本                      │
│  即使 XSS 注入了脚本，浏览器也不执行                   │
│  相当于最后一道防线                                    │
│                                                       │
└──────────────────────────────────────────────────────┘




┌──────────────────┬────────────────────────────────────┐
│  类型             │  说明                              │
├──────────────────┼────────────────────────────────────┤
│  存储型 XSS      │  恶意脚本存到数据库里               │
│  (最危险)        │  其他用户访问页面时从数据库取出执行  │
│                  │  比如评论区注入脚本                  │
│                  │  所有看到这条评论的人都中招           │
├──────────────────┼────────────────────────────────────┤
│  反射型 XSS      │  恶意脚本放在 URL 参数里            │
│                  │  服务端把参数原样返回到页面           │
│                  │  用户点击恶意链接就中招               │
│                  │  比如搜索结果页回显搜索词             │
├──────────────────┼────────────────────────────────────┤
│  DOM 型 XSS      │  纯前端的 XSS                      │
│                  │  JS 直接把用户输入插入 DOM           │
│                  │  不经过服务端                        │
│                  │  v-html 就属于这种                   │
└──────────────────┴────────────────────────────────────┘
