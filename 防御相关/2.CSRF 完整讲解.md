┌──────────────────────────────────────────────────────┐
│  CSRF 攻击原理（跨站请求伪造）：                       │
│                                                       │
│  第一步：你登录了银行网站 bank.com                     │
│         浏览器存了登录 Cookie                          │
│                                                       │
│  第二步：你点开了一个恶意网站 evil.com                  │
│         恶意网站页面里藏了一个请求：                    │
│         <img src="bank.com/transfer?to=hacker">      │
│                                                       │
│  第三步：浏览器发请求到 bank.com                       │
│         自动带上了你的 Cookie！                        │
│         bank.com 以为是你本人在操作                    │
│         钱就转走了                                     │
│                                                       │
│  核心原因：                                            │
│  浏览器发请求时会自动携带目标域名的 Cookie              │
│  不管这个请求是从哪个页面发出的                         │
└──────────────────────────────────────────────────────┘




┌──────────────────────────────────────────────────────┐
│  CSRF 防御方案                                        │
│                                                       │
│  方案一：CSRF Token（最主流）                          │
│  · 后端生成随机 Token，返回给前端                      │
│  · 前端每次请求带上 Token                              │
│  · 后端验证 Token 是否合法                             │
│  · 恶意网站拿不到 Token，伪造请求会失败                │
│                                                       │
│  方案二：SameSite Cookie                              │
│  · 设置 Cookie 的 SameSite 属性                       │
│  · SameSite=Strict → 跨站请求不带 Cookie              │
│  · SameSite=Lax → 只有导航到目标站才带                │
│  · 从根源解决自动带 Cookie 的问题                     │
│                                                       │
│  方案三：验证 Referer / Origin                        │
│  · 后端检查请求的 Referer 头                          │
│  · 如果不是自己站点发出的就拒绝                        │
│  · 但 Referer 可以被篡改，不够可靠                    │
│                                                       │
│  方案四：关键操作二次验证                              │
│  · 转账等敏感操作要求输入密码或验证码                  │
│  · 即使 CSRF 攻击成功，也过不了二次验证                │
│                                                       │

└──────────────────────────────────────────────────────┘

CSRF："CSRF 利用浏览器自动带 Cookie 的机制，从恶意网站伪造请求。防御核心是 CSRF Token + SameSite Cookie，关键操作加二次验证。"
